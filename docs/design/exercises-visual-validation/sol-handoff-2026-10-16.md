## 1. 范围与保留清单

范围是 `ExercisesPage` 的准备及导入呈现，及必要的局部状态协调。题库、当前作答面、独立单题练习作为回归面，不借机重做。MainLayout/AppRail/全局CSS/笔记/教材/错题页不属于本轮实现范围。工作区已有用户未提交修改，实施前识别并保留。

必须保留：

- ScopeSelector 的学科/教材语义及全局上下文联动；不是随意把空教材解释为跨所有题库聚合。
- `usePracticeSession` 的 sessionLimit（1–200，默认20）、sessionShuffle、状态/关键词筛选、单题入口、暂停/恢复/结束和未确认作答恢复。
- `.docx`/文本PDF、独立答案文件、来源/章节、辅助修复及发送前明确确认。limit=200、llm_max_items=20 不变。
- 教材章节、小节稳定heading标识；无outline时文字回退；exercise_sections/examples/all_pages；物理页范围；鉴权PDF预览、翻页、抽取当前页。无PDF仍可使用已导入教材抽取。
- 候选题干、答案、解析、来源、学科、章节、题型、难度、tags、linked_concepts、origin及重复/警告信息。当前没有编辑入口的字段也必须透传，不得因新表单丢失。
- 全选/取消、异常/重复过滤、相邻合并、第一空行拆分、预览/编辑、重复跳过、真实入库回执、批次回滚。
- ManualExerciseDialog、ExerciseDetail、答案生成与现有作答状态合同。

## 2. 组件关系及代码所有权

页面保留应用协调，领域hooks继续持有业务状态。只新增以下局部呈现模块（允许在同文件内先组织，按代码体量拆文件；不为每一行标题造组件）：

| 模块 | 责任与复用 | 需要改变什么 |
|---|---|---|
| `PracticePreparation` | 范围/数量/顺序/开始，辅区资源摘要；复用 ScopeSelector、SegmentedControl、practice hook | 替换现有横向设置条；已有会话继续入口；空库与筛选无结果分开 |
| `ExerciseImportSetup` | 教材/文件两种source分支，调用当前analyze handlers | 撤销380px常驻来源侧栏；一个来源一个表单；请求状态在原位展示 |
| `CandidateReviewWorkspace` | 索引、当前题正文、编辑、原文模式、提交栏；复用候选hook和candidateOperations | 将候选整题列表改成轻索引＋单题正文；保留原始候选顺序/ID |
| `ImportReceipt` | success / partial / unknown，真实count/skipped/batch_id及后续动作 | 回执不能被load()的message清除；不使用最新批次冒充本批次 |

`CandidateReviewWorkspace`内部可拆局部CandidateIndex和CandidateDocument；不新增全局 PageBuilder、WorkflowEngine、通用三栏框架或另一个设计系统。

现有 `SimpleMarkdown` 负责正式题干/答案/解析渲染；原型直接使用KaTeX是预览成本选择，不能替换正式Markdown管线。已有 `WorkspaceActionBar` 若可占据布局流且不覆盖内容则复用；否则给它最小显式variant，或先在feature内实现底栏，不用全局CSS覆写全部动作栏。

新增 `features/exercises/exercises.css`（或现有同域CSS文件）拥有 `.exercise-preparation`、`.exercise-import-setup`、`.exercise-candidate-review` 的规则。原型 `.content`、`.field`、`.two`、`h1` 等全局选择器**不得照搬进生产**。不得通过继续往 StudyDesk.css / ApprovedWorkspace.css 末尾叠规则实现本设计。ExercisesPage 当前导入 notes.css；本轮只在确认依赖和等效局部样式后去除该跨域依赖，不顺带整理全产品CSS。

## 3. 页面与状态转换

```text
练习视图
├─ overview加载/失败 → 就地反馈与重试（不是空库）
├─ 当前scope无题 → 教材抽取 / 文件导入 / 手动录入 / 调整范围
├─ 筛选无结果 → 清筛选 / 调整范围
├─ active或paused会话 → 继续优先 / 明确结束
└─ 有题且无活动会话 → 范围→题量→顺序→创建既有PracticeSession

导入视图
source → analyzing → review → submitting → receipt
                  ↘ source-error       ↘ commit-unknown
review → 返回来源（保留候选）→ 继续校对
source的新请求 → 明确替换旧候选 → 新review
receipt → 练习准备 / 题库 / 剩余候选
```

这是前端显示阶段，不增加后端状态机。`workspaceMode`与导入阶段分离；切到练习再回来应恢复同一内存中的导入阶段，而非因重挂载丢失。

具体行为：

1. 来源选择、设置值、当前请求的scope快照、候选batch草稿、当前候选ID、选中ID集合、过滤条件各有一个明确owner。切换显示模式不重置候选。
2. 已有候选时，返回来源不删除；更换教材/学科或重新解析在真正替换前确认。先保护旧值再调用setBookName/setSubject，不能等effect清空后才提示。请求带前端generation/scope标识，旧请求迟到结果不得进入新scope。
3. analyzing不是后台Job：可以保留已挂载视图的HTTP请求；禁止并发重复分析；切页不显示“已取消”。关闭/刷新时仅提示当前内存工作会丢失，不承诺恢复或取消服务端。
4. 分析返回零候选留在来源页，展示extract warnings和可用原文；返回候选时展示答案匹配数量、修复摘要/全局警告，不能在新布局里丢掉旧message中的有效反馈。
5. 索引项点击只切当前题；复选框只切批量选择，二者不可混同。筛选后当前题若不可见，转到首个可见项；筛选零结果时显示“没有此类候选”，仍保留整个批次及全量选择。
6. 全选/清空的作用域保留既有全批次语义，明确文案；不能让过滤后的全选悄悄改变合同。选中状态不得变为已校对徽标。没有警告也仍是待人工检查。
7. 索引标题使用现有题干首行/可靠字段的确定性摘要（最长两行，完整内容在正文）；不要新增模型调用来生成漂亮标题。原型的语义标题是固定样例。
8. 阅读态题干和答案展开；解析/元数据折叠；编辑态保留全部现有可编辑字段，改动即更新内存草稿，不新增“正式保存候选”假概念。切题后回到文档顶部；返回同题/切原文保留所需阅读位置。恢复焦点，避免每次输入丢光标。
9. 合并只允许原顺序相邻题，保留candidateOperations实现；拆分按其第一空行算法，显示会清空首题答案/解析及需复核。拆后选择两新题，merge后选择合并题。不要复制原型演示算法进业务。
10. 题干编辑遵守现有duplicate_of清理语义；警告依据现有数据保留。缺答案不阻断；空题干提示补全或取消选择。若有其他阻断字段，以实际API合同为准，不随意新增一组“校对通过”门槛。
11. 提交前简短确认选中数、重复/警告；用户明确确认后调用当前batch-add。submitting锁住提交，候选直到可靠结果回来前不删除。
12. 回执绑定返回的batch_id，以count/data/skipped为依据。0条实际入库显示“没有新增题目”，部分跳过说明原因；未提交候选仍可继续。按确定回执清理已处理项，不能删掉未知或失败项。
13. 网络断开时保持unknown。既有batch list只用于核对；可靠batch_id则按身份匹配，无身份不可把最新一条当成这次成功。无自动写重试。本轮不引入后端幂等新协议。
14. 回滚按钮只指向回执对应的active批次，确认实际批次与数量；权限/业务拒绝就呈现拒绝，不宣称任意情况下都能安全撤销。

## 4. 布局验收规格

以最终截图为任务参照，不要求跨阶段套同一模板。

- 顶部工作区导航固定，正式Electron拖拽区域保留，按钮/表单不在drag区。导航壳宽度及折叠行为不在本轮修改。
- 练习：有界外容器956px；宽窗口左右38px；右摘要268px、间隔46px。窄窗口左右32px，右摘要224px、间隔28px。主要操作置于设置完成处；题目示例最多3条、无答案，并明确不代表下一轮顺序。
- 空库：外容器770px，两条带图标的整行来源入口，手动录入次级。不画空列表，不展示无意义的零统计阵列。
- 来源：外容器810px（窄窗760px），同一来源下最多两列表单；教材范围单独一行，章节/抽取模式同排；文件区先文件后答案文件、再归属。来源名、章节、页码、修复按相应来源展开。没有教材时给明确选择/准备入口，不展示不可用假选项。
- 校对：左索引224px（窄窗194px），右正文余宽；正文外容器max810px，左右32/24px。总高度为工作区剩余高度，`min-height:0`贯穿flex/grid链路。头部任务信息约140px；底栏至少76px，在流内占位。列表与正文各自滚动；不让浏览器整页和内部三层同时纵滚。
- 原文：宽窗口临时收索引，正文与原文各半；工作区可用宽度<900px时改候选/原文切换。不加永久第三列，不假设原文有逐题精确定位；若数据只是extract.text，明确是整段提取原文。
- 排版：题干16px/1.9；答案15px/1.85；标题28px（校对24px）；辅助12px。禁止为适配1024全局缩成12px题干。公式超宽仅该公式横滚、无纵滚；长文件名和错误说明自然换行。
- 1024×768基础状态的开始/解析主操作首屏可见；展开高级项、错误反馈或长表单可以滚动。校对底栏始终可见，正文末尾可滚动到且不被遮挡。1024长题答案不要求首屏完整展示。
- 低于本轮尺寸时先将准备辅区移到下方，再降为单文档；不改全局导航规则。本轮不以手机稿为验收目标。

原型使用本地颜色/字体变量，仅用于明确视觉关系。生产映射到现有基础token，必要局部尺寸由feature拥有，不增加全产品例外类或为此扩充texa-ui-system。

## 5. 分阶段实施与停止点

**批次1：准备与来源。** 新构图接既有hooks；完成有题/无题/筛选空/活动会话，以及两来源、文件就绪、高级项/错误。提供1280/1024实际Electron截图，Astra确认后继续。不能用原型截图替代。

**批次2：候选校对。** 接真实候选、原文、编辑/选择/过滤/合并/拆分，保留scope及迟到请求隔离。提供长题/矩阵/缺答案/重复/编辑/原文切换截图和操作结果。

**批次3：回执、恢复与回归。** 接真实batch回执，覆盖部分跳过/0新增/结果未知；保留已挂载返回。完成下列测试及关联面回归，Astra根据真实渲染作最终设计验收。

每批次都可以修正实现细节。以下情况必须反馈设计冲突而非自行改构图：现有壳导致题干净宽不足；API无法支持画面承诺；恢复必须引入数据库或Job；独立滚动破坏键盘/阅读操作。不得为赶进度退回旧布局再叠CSS。

## 6. 验证包与验收标准

实现验证使用隔离fixture或临时测试数据目录，不写正式题库。保留现有candidateOperations/directPractice测试；补具有真实状态风险的测试：切视图草稿不丢、scope变更与迟到请求隔离、连续提交防重、部分回执/unknown不清空、实际batch身份回滚。修改领域逻辑时补相应合同测试；不要给每个padding写测试。

执行前端类型/构建及相关测试。实际命令可使用当前环境Node/npm：`npm run build`、`npm test -- src/features/exercises/hooks/candidateOperations.test.ts src/features/exercises/directPractice.test.ts`，再加本次新增测试。纯视觉检查之外，必须跑真实Electron入口（含拖拽、尺寸和已挂载路由行为）；不要以浏览器成功代替桌面验收。

截图包必须同时包含：

| 场景 | 1280×820 | 1024×768 | 验收依据 |
|---|---|---|---|
| 有题准备、无题、筛选空、活动会话 | 必须 | 必须 | 主次清楚，空状态准确，不覆盖活动会话 |
| 教材/文件初始、文件就绪、高级项展开 | 必须 | 必须 | 一种来源一套表单；重要条件不靠placeholder |
| analyzing、无候选、失败 | 必须 | 必须 | 真实状态，无伪进度，恢复动作可用 |
| 候选长题、矩阵、缺答案、重复、编辑 | 必须 | 必须 | 题干是重心；元数据不抢视觉；无裁公式 |
| 原文对照及返回 | 并排 | 切换 | 没有三栏压缩，当前候选和修改不丢 |
| 确认、成功/部分跳过、0新增、unknown | 必须 | 必须 | 返回的实际数量/身份，错误不被刷新清掉 |
| 200条候选与超长文件/错误信息 | 必须 | 必须 | 索引仍可用，底栏稳定，无整页横向溢出 |

跨页只做防回归：题库展开/单题练习、当前作答/暂停恢复、手动录入弹窗、教材PDF选页；再各取学习、笔记、错题、教材代表页确认全局壳、字体、表单、动作栏未被局部CSS污染。不在这些页面顺手修设计。

每组证据记录代码revision/未提交差异、Electron版本、视口、fixture及字体加载状态。截图对比不能只看像素差；Astra分别判断：任务主操作是否明确、阅读宽度和段落节奏是否成立、警告是否可理解、辅助信息是否抢主体、长内容是否仍保持同一构图。构图错误即使build与tokens全通过也退回。

**Sol交付的是实现和证据，Astra负责设计复审，用户确认后才能进入下一授权阶段。** 本文不授权数据库、解析、模型调用流程、学习Runtime或全产品Design System重构。
