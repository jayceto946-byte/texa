## 1. 产品事实先于布局

实际检查 `ExercisesPage.tsx`、`usePracticeSession.ts`、`useExerciseImportCandidates.ts`、`candidateOperations.ts`、`useTextbookImportOutline.ts`、相关类型及 `backend/api/exercises.py`。以下事实决定设计，不能被视觉稿覆盖：

| 源码事实 | 对设计的约束 |
|---|---|
| 已有 practice / bank / import 三个视图；会话支持 active / paused / completed / abandoned | 已有题目用户直接准备练习；已有活动会话首先继续，不强迫重新导入 |
| practice 按教材范围、学科、状态、关键词、数量、顺序创建会话 | 这些选择必须保留；不能把三条题目示例伪装成下一轮精确题单 |
| overview 最多读取 100 条；练习题量 1–200，当前默认 20 | 区分已加载、统计总量和实际组卷数量；原型选择 10 仅是样例状态，不建议擅改默认 |
| 上传与教材抽取请求 limit=200，llm_max_items=20 | 20 是模型修复上限，不是候选总量上限；不能将原型的 6 题当生产容量 |
| `.docx` / 含文本 PDF；独立答案文件；教材章节/小节/物理页；三种抽取模式 | 来源切换只隐藏无关表单，不能删功能；扫描件须先 OCR，辅助修复不等于识图 |
| 分析是普通 HTTP 请求，教材抽取超时 60 秒；候选为 React 内存状态 | 不设计伪进度、暂停、重启续传。应用内返回与刷新后恢复必须区别说明 |
| 初始全选；异常筛选、重复标记、相邻合并、空行拆分；答案可为空 | 选择不等于校对完成；缺答案是可处理提示，空题干才是应阻止提交的缺项 |
| batch-add 返回 count/data/skipped/batch_id；allow_duplicates=false | 成功用服务器回执呈现；不能用选中数宣布入库数，不能误回滚别的“最新批次” |

## 2. 当前问题与两种方向

用户来练习页通常为了开始或继续作答；来导入页为了把一份具体材料变成可信、可用的题目。原页面让两个来源的所有设置同时占据左侧，尚不存在的候选却永久占据右侧。这个分栏服务了实现结构，没有服务当前任务。练习准备则把重要配置压成工具条，剩余空间失去用途。两者都不能靠微调 padding 修复。

| 比较 | A：阶段展开，推荐 | B：题库常驻的资源工作台 |
|---|---|---|
| 空间 | 准备采用有界画布；校对展开为索引＋正文 | 题库始终在主区，右侧约 310px 放练习或导入设置 |
| 操作与内容 | 先决定来源，出现候选后让内容接管 | 资源浏览与动作配置并行 |
| 初始/空状态 | 无题时只有来源路径；未解析时无结果占位栏 | 空题库需要在大主区解释，侧区仍保留配置 |
| 校对与确认 | 来源表单退出主体，校对正文与固定提交栏接管 | 候选替换题库列表，来源侧区可持续保留 |
| 注意力 | 每个阶段只有一个主要工作面 | 主区浏览与侧区操作同时争夺注意力 |
| 适合 | 日常直接练习；集中导入一次、校对一批 | 经常浏览、比较和整理大量题目，再组织练习 |
| 相比原版 | 去掉空结果栏，给长题干足够阅读宽度 | 消除小工具条，长期资源上下文更强 |
| 代价 | 返回来源多一步；阶段切换必须保留状态 | 窄侧区无法舒展文件/页码表单，导入容易再次堆叠 |
| 视觉风险 | 若标题与步骤过大，校对正文被挤压 | 大列表容易抢走“开始练习”，空库时重新失衡 |

两种方案均有可渲染空间草案。B 只做足够比较的练习/导入入口构图，未假装完成全部交互状态。见 [B 练习](../../../artifacts/design/exercises-validation/screenshots/1280-direction-b.jpg) 与 [B 导入](../../../artifacts/design/exercises-validation/screenshots/1280-direction-b-import.jpg)。

**选择 A 的理由**：Texa 的主任务是学习；题库管理已有独立入口。把题库长期放在中央，会让开始练习变成浏览资源后的附属操作。A 给简单任务一个短路径，给人工校对一个宽工作面，也不要求新建后端工作流。B 的资源浏览优势保留给既有题库视图，不混入默认练习准备。

## 3. 具体设计决策

| 决策 | 旧方案的问题 | 新构图与收益 | 影响及判断方式 |
|---|---|---|---|
| 练习设置是主区，资源摘要是辅区 | 配置挤在横条，空白没有意义 | 范围→题量→顺序→开始，右侧仅说明当前题目及示例 | 练习准备；已有题用户不进入导入也能开始，主要操作首屏可见 |
| 无题状态直接给来源路径 | 空练习框和禁用操作不能帮助下一步 | 两条整行入口：教材抽取、文件上传；手动录入为次级 | 真空库；不能把筛选无结果或接口失败误判为无题 |
| 来源为互斥选择，后续配置按需展开 | 两种导入方式并排堆在同一窄列 | 选中一种来源后只展示相关配置；物理页/来源名/修复为渐进展开 | 导入初始、文件就绪；主操作跟随表单，长文件名能换行 |
| 校对改为索引＋一题正文 | 一长串完整候选与徽标使阅读、定位混乱 | 左侧选中/异常/序号，右侧题干、答案、解析；编辑在原位 | 校对；长题、矩阵、缺答案都可读，切题不丢修改 |
| 原文对照是阅读模式 | 永久三栏会损害题干和原文可读性 | 宽窗口暂收索引，正文与原文 1:1；窄窗口切换阅读 | 校对；两边都不靠缩字适配。代价是窄窗口无法同时看两份内容 |
| 确认入口稳定，完成回执独立 | 提交状态混进列表消息，刷新可能清掉成功反馈 | 底栏始终显示选择数；提交前一次明确确认；完成显示实际数量和下一步 | 入库；重复、部分失败、网络未知不能被“成功”一词掩盖 |

这不是删文字以求极简：保留了来源要求、扫描件限制、错误修复指引、选中与校对的区别、实际入库回执和恢复边界。删除的是重复流程说明及尚不存在的结果容器。

## 4. 构图、层级与窗口行为

全局导航只是原型背景，正式实施复用现有外壳。最终原型侧栏占位为宽窗口 232px、1199px 以下 208px，与现有桌面规则一致；本轮不授权修改 AppRail。顶部 56px 工作区栏始终保留练习/题库/导入切换，正文从其下开始。

| 工作面 | 1280px | 1024px | 滚动/操作 |
|---|---|---|---|
| 练习准备 | 外容器 max 956px（含左右各38px内边距）；右摘要268px，间隔46px，左侧剩余 | 左右内边距32px；右摘要224px，间隔28px | 内容整体滚动；开始按钮跟随配置，不悬浮压住内容 |
| 无题 | 外容器 max770px；较大上方留白，入口整行 | 同一结构，左右32px | 普通页面滚动，不为填满屏幕添加卡片 |
| 导入准备 | 外容器 max810px，实际表单734px | 外容器 max760px，表单696px | 标签贴近控件；主按钮位于表单末尾；高级项展开后允许滚动 |
| 校对 | 索引224px，正文占余宽；正文外容器 max810px | 索引194px，正文占余宽；内边距24px | 顶部任务信息固定；索引和正文独立滚动；底栏至少76px，在布局流中占位 |
| 原文对照 | 收起索引；正文/原文1:1，间隔28px | 不并排：候选/原文切换 | 保留当前候选、编辑、选择和返回位置；正式实现两文档各自保存滚动位置 |

1100px 是原型的内容构图切换点；正式实现应使用工作区实际可用宽度，而不是假定全屏像素。建议对照模式在可用宽度 <900px 时切为单文档；准备页 <700px 时辅区移到底部。低于本轮1024px范围的规则只作为退化要求，不能宣称已验证手机布局。

标题 28px/1.35，校对页标题24px；任务段标题18–19px；控件13–14px；题干16px/1.9，答案15px/1.85，辅助说明12px。暖纸色 #faf9f6、正文 #282b30、次级 #6d7179、分隔 #dfdfda、蓝色 #465dca。输入表面用白色，列表索引用略深暖灰；无装饰卡片阵列、渐变或大阴影。实际接入优先映射现有语义 token，不能仅因数值略有不同全局改 token。

始终可见的是工作区导航、当前任务名称，校对时还有来源摘要与提交栏。只在相关阶段出现的是源表单、候选警告、编辑字段、回执。解析置信度进入题目属性，不作为显眼的“可信”徽标。题干、答案和确实需要人工检查的错误比元数据优先。

## 5. 状态组织

| 用户/状态 | 画面与下一步 | 不得误导 |
|---|---|---|
| 首次进入无题 | 来源路径＋手动录入＋调整范围 | 不能因辅助统计失败显示空库 |
| 有可用题 | 范围、题量、顺序、开始；题目摘要 | 导入非必经步骤；示例不等于本轮题单 |
| 已有活动/暂停会话 | 继续当前练习优先；明确结束后新建 | 不覆盖已有会话或丢作答 |
| 选择来源 | 教材/文件切换，只展开一种 | 保留两条真实路径与必要字段 |
| 文件已选未解析 | 文件名、更换、独立答案文件、归属范围 | 不暗示已经上传或入库 |
| 正在抽取/解析 | 同一来源画布显示请求状态，禁重复提交 | 无伪百分比、取消成功、后台断点恢复承诺 |
| 无候选结果 | 保留来源、展示抽取警告，调整范围或重选文件 | 不直接跳成功，不隐藏原文中有用的提取结果 |
| 已有候选 | 索引＋正文，默认继承全选；逐题阅读/修改 | 选中不等于已校对 |
| 部分候选有问题 | 列表标识＋当前题明确警告；异常/重复筛选 | 缺答案可留空；空题干须补全或取消选择；置信度非正确率 |
| 入库中 | 保留候选，禁重复提交，明确正在入库 | 不提前清空未确认候选 |
| 入库成功/部分跳过 | 真实回执，去准备练习/查看题库；剩余候选可继续 | 0条入库不能套用“题目已加入”；回滚绑定本批次 |
| 分析失败/超时 | 保留文件与输入，原因＋可执行恢复动作 | 分析请求没有写题库；可由用户重试，不自动付费重试 |
| 提交中断、结果未知 | 保留候选，先核对导入批次 | 不直接重发写操作；“最新”不是可靠身份 |
| 应用内返回 | 有候选就展示继续校对；请求仍在则返回解析状态 | 返回来源不丢修改；重新解析前明确替换影响 |
| 刷新/重启 | 坦诚说明未入库候选不能恢复，重新选文件；已入库仍在 | 不为本轮设计临时新增持久化或后台 Job |

## 6. 实际视觉验证与迭代

在 Codex 浏览器实际渲染，使用1280×820、1024×768视口。核心四状态各两张，另外保存文件就绪、编辑、失败、原文对照、成功和 B 方向；样例含长题干、泰勒展开、积分、参数矩阵与分段函数。截图等待本地字体完成加载，未以无文字的字体加载瞬间作为证据。

第一版截图保留为 `screenshots/v1-*`。查看后作了这些调整：

1. 将教材标签、控件、提示包成一个字段组，消除被父级 grid 等距拆散的松散关系。
2. “可选”变为标签内次级文字，修正文件表单两列错位。
3. 缩短练习准备分组间的过度垂直距离，保持1024窗口主操作有底部余量。
4. 固定候选筛选的两行标签/数量结构，避免窄窗口随意换行。
5. 补上返回来源后的继续校对入口；验证修改仍保留。
6. 将外壳占位改回现有232/208px后重新截图；没有靠缩窄产品导航获得空间。
7. 在系统显示滚动条的环境下移除公式自身的纵向滚动，仅允许超长公式横向滚动。

原型交互实测：题干编辑→阅读预览→返回来源→继续校对，修改仍在；清空选择后入库禁用；全选6题确认后回执展示5入库/1重复；原文窄屏切换；长矩阵渲染。源码语法检查通过。解析、组卷、入库和回滚均没有调用正式API；未运行正式业务测试，也没有把浏览器原型当 Electron 集成证据。

### Astra 五项评审

| 维度 | 判断与证据 | 未完成/取舍 |
|---|---|---|
| Functional Correctness | 设计保留两来源、范围、练习配置、候选编辑/筛选/合并/拆分、回执和恢复边界；空选择禁用等已在原型操作 | 固定样例不是业务正确性证明。真实解析、200题容量、批次回滚、会话恢复待实施验收 |
| Interaction Quality | 用户可绕过导入直接练习；校对不再反复穿过源表单；修改与提交责任清楚 | 一题一页增加切题；快捷键和真实批量校对效率尚未验证 |
| Visual Composition | 初始来源页有单一重心；校对让数学正文而非徽标成为主角；空状态留白围绕真实选择 | 1024长题答案需滚动，原文需切换；不压缩正文去追求首屏塞满 |
| Product Consistency | 沿用暖中性、蓝色动作、Harmony/KaTeX、Texa导航语义；准备与阅读拥有不同密度 | 原型外壳是视觉背景，正式壳的拖拽区/导航交互未复制，须 Electron 复审 |
| Maintainability | 两类内容构图：有界准备画布、索引/文档校对。来源差异集中在表单，复用现有领域hooks | 不能复制原型的全局选择器；需局部命名空间和清晰的状态所有权 |

决定整体质量的是：阶段改变空间分配、主体与辅助的比例、长题干的阅读尺度、表单字段的近邻关系、提交动作的稳定位置。这些不能用“符合字号和色值”替代。

真实用户验证仍需回答：三条示例是否有助于确认范围；高级项折叠是否妨碍按物理页抽题；窄屏切换原文是否降低校对效率；6题到50/200题时索引是否仍容易定位。建议用已有题用户直接开始、首次上传带答案文件、校正公式并排除重复三项具体任务观察，记录误操作和退回次数，而不收集抽象喜好评分。
