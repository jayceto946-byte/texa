# Texa Design Architecture & Experience Audit

日期：2026-10-15。角色：Principal Product Designer。状态：独立审计与设计提案，尚未批准实施。

**核心判断：Texa 已形成可以辨认的视觉语言，但还没有形成足以持续产出好页面的设计架构。它的优势是阅读与学习资产的可信边界；主要短板是任务组织、页面构图和跨页连续性。继续把其他页面修成“像批准截图”，不会解决这些问题。**

本报告不把 texa-ui-system、现有组件结构或此前 Astra/Sol 的通过记录视为不可质疑的标准。第一轮判断已在阅读这些设计材料前[独立记录](texa-independent-design-findings-2026-10-15.md)。后续规范只用于解释现状、辨认差距与评估实施成本。

## 2. 从学习任务判断产品，而不是从页面清单判断

Texa 的核心价值是：**帮助学习者理解教材中的问题，完成独立练习，把理解和错误沉淀为下次可以使用的资产。**

一次有效学习通常包含下列关系，用户可从任意环节进入，不需要被强制走完整条流程：

```text
教材 / 题目 → 提问与理解 → 核对来源 → 整理为笔记
                    ↓
                独立作答 → 对照与归因 → 错题资产 → 到期重做

目标与专注：为上述活动提供执行上下文
配置与维护：保证上述活动可用
```

这里有三个应当保持的区分：

- **解释与事实依据**：模型解释可阅读，教材来源可核对，两者不混为一体。
- **活动与资产**：一次问答、一次作答、一次专注是活动；笔记、错题是可长期维护的资产。页面切换不应破坏活动，也不应自动保存为资产。
- **本次结果与长期掌握**：做对一次、计时结束、AI 执行结束都不等于已经掌握。

目前导航的“学习、目标与任务、复习、笔记、错题、练习、教材”混合了活动和资产，但**七个入口不是需要解决的根因**。现在把它们压成“学习／资源”两项，会增加寻找成本。优先保留高频直接入口；通过稳定的对象标题、来源链接、范围与返回路径解释关系。是否调整导航分组或顺序，交给真实任务验证，不先重命名全部产品。

### 九个维度的质量判断

| 维度 | 当前判断 | 证据与设计含义 |
|---|---|---|
| Information Architecture | 对象基本齐全，学习路径的组织弱于功能组织 | 教材以维护为中心；笔记生成藏在会话菜单；复习与练习边界需要通过操作而非术语解释 |
| User Workflow | 有恢复、保存、确认等坚实基础，跨页承接仍碎片化 | E07/E13 值得保留；E03 总入口并不代表整个混合队列；E05 的空态要求用户记住别处的入口 |
| Interaction Design | 局部交互较完整，行为语义尚未完全一致 | 有键盘选择、模态焦点、明确确认；练习“已掌握”和复习“独立做对”表达不同层级的结论 |
| Visual Hierarchy | 阅读较强，管理和任务页面不稳定 | 聊天主轴清楚；错题重复题干、目标重复状态、练习设置缺少主体构图 |
| Layout & Spatial Composition | 有基本秩序，仍偏向套容器 | 宽列表合理，短准备表单全宽不合理；编辑、校对缺少各自构图 |
| Typography & Content Density | 字体与中文正文已可用，密度角色过粗 | 16px 阅读与紧凑工具区有意义；把管理页按钮普遍压到 28px/12px 缺少任务区分 |
| Component Semantics | 有良好基础组件，使用契约不完整 | Tabs、SegmentedControl 已分离；Goal 用按钮组加 select 控同一筛选，Notes 自建 tabs，语义和状态不能只靠类名统一 |
| Visual Consistency | 色彩、背景和边线比任务布局更一致 | 不是“每页都像不同产品”，而是同一语言下有些页面没有被完整设计 |
| Perceived Product Quality | 已脱离原始原型，尚未达到成熟学习工作台 | 原因是任务解释与空间安排不够自然，不是缺少插画、动画或更多品牌装饰 |

不以未经用户研究的 6.8/10 等数字包装判断。此次证据也不足以认定存在全局 P0 视觉故障。

## 3. 保留、改进、重组与重设计

| 处理 | 页面 / 模式 | 判断与边界 |
|---|---|---|
| 保留，作为参考样本 | 学习回答、笔记阅读、并排来源 | 连贯文章、公式排版、来源就地展开、输入与阅读连续性正确；保留原则，不冻结全部像素 |
| 保留并校准 | 复习独立重做、错误恢复、版本冲突 | 教学顺序和数据保护是质量资产；不能因“去提示”而削弱 |
| 局部改进 | 笔记/错题列表、目标主从布局、设置、专注控制 | 统一控件语义、范围和动作层级；不把已有的 Goal/task/focus 再做一次大重构 |
| 重组信息架构 | 教材入口、复习与练习的衔接、会话到笔记 | 先改变默认看见什么、下一步通往哪里；CSS 无法解决入口承诺错误 |
| 重新设计主内容区 | 笔记编辑、练习准备、错题详情 | 当前结构阻碍写作、决策或纠错；仅统一字号和 gutter 无法改善 |
| 发展专门模式 | 习题候选校对、图片/原文比对 | 属于对照验证任务，不能按普通表单或阅读页设计 |
| 废弃 | 两图永久权威、全页统一压缩、按卡片数量评优、只看溢出验收 | 这些做法可产出“符合规范但不好用”的页面 |

具体例子：错题详情里，“题目很长”不是缺陷；把同一题干在大标题和正文重复，才是结构问题。笔记列表只有一条时的空白不必填满；应让这条笔记的内容、来源和打开动作形成清楚的局部构图。

## 4. 对现有 texa-ui-system 的审计

### A—E 归因

| 分类 | 发现 | 处理方式 |
|---|---|---|
| A 规范正确，实现未充分遵守 | “同一语义用同类控件”合理，但 Goal、Notes、Library 各自表达筛选和选中；共享类的效果依赖父选择器 | 先确定它们究竟是导航、筛选还是值选择，再用相应组件；不把所有条形控件强制改成同一种 Tab |
| B 有规范，约束不足 | “学习内容优先”“层级清楚”不能指导短表单、比较编辑、任务队列；状态文档没有给出不同阶段如何保留工作上下文 | 用可运行示例与组合模式补足；文档只解释为什么 |
| C 规范本身不合理 | `SKILL.md` 将学习/教材两张图定义为 approved visual ground truth，并要求保留构图；它们无法为笔记写作、候选校对、独立作答提供充分依据 | 废弃全产品权威身份，改为有范围、有版本、可替换的参考案例 |
| C 规范本身不合理 | 两种 archetype 把 collections、records、forms、review actions 都放进 management workspace | 用任务特征决定构图；“管理”不再作为所有非聊天页的默认答案 |
| C 实际规则不合理 | 共享 CSS 按 management 父级把按钮统一变成 28px/12px | 改成显式控件密度；密集表格可以紧凑，关键学习操作不应自动继承紧凑模式 |
| D 规范不能代替设计判断 | 题干是否需要重复、是否必须看到原文、某页空白是否合理、确认动作是否足够清楚 | 通过有内容的页面设计和任务评审判断，不能再加一条“禁止空白/卡片”的规则 |
| E 产品流程问题 | “开始本次复习”优先进入错题会话，概念走另一流程；笔记库只能提示回到会话菜单；练习评价把单次表现表达为掌握 | 先确定操作合同、入口和结果语义，再改界面；不伪装成 token 改造 |

### 为什么它没有阻止问题反复出现

**第一，权威相互重叠。** [index.css](../../frontend/src/index.css) 定义基础尺寸与色值；[theme.ts](../../frontend/src/theme.ts) 写入主题值；[ApprovedWorkspace.css](../../frontend/src/layouts/ApprovedWorkspace.css) 再定义 workspace roles；[StudyDesk.css](../../frontend/src/layouts/StudyDesk.css) 区分学习/教材特例；其后还有移动和桌面修整。`MainLayout` 的导入顺序成为实际规则的一部分。问题不是 CSS 文件多，而是同一职责在多层被反复决定。

**第二，页面分类与组件 API 脱节。** 普通按钮往往只是类名，所在祖先决定尺寸。Sol 看见 `app-primary-button` 并不能保证它在页面、Portal 或不同路由得到相同效果。具体修复很容易继续追加更强选择器。

**第三，“删掉旧规则”之后，可执行替代物不足。** 历史审计已经提出过 tokens、组件和减少实现锁定；当前技能也已很简短。这说明继续精简/扩充 Markdown 不是主要解法。缺少的是能演示好页面的组合实例和稳定的实现归属。

**第四，验收偏向已知缺陷的关闭。** 既有 [Visual Review Board](../qa/VISUAL-REVIEW-BOARD.md) 有跨域抽查、真实交互和有限结论，值得复用；但“改动符合既有参考”不等于“这个页面最适合当前任务”。本轮必须允许推翻参考，而不只是寻找偏差。

**第五，自动检查保护的范围窄于开发者容易理解的 PASS。** 当前 `texaUiContract.test.ts` 已不再是旧版的纯实现锁定，但仍有源码字符串检查；token 引用检查只读 `index.css`。`theme.test.ts` 已验证主题完整性、部分文字对比度和默认色同步，不能说没有工程约束。缺口是全样式图谱、渲染结果、跨页影响和真实任务验收。

**第六，页面加载顺序是尚待验证的跨页风险。** 例如 notes.css 中存在会话菜单/历史列表的全局选择器，而路由按需加载，页面又会保留挂载。由此存在“访问笔记后影响聊天”的机制风险；本轮未复现，不能当成已确认 bug。后续应专门验证 A→B→A，而不仅是每页单独刷新截图。

## 5. 建议的 Texa Design Architecture

### 5.1 一个产品语言，五种任务构图

```text
产品与领域合同：对象、范围、来源、保存、任务状态、结果含义
                         ↓
视觉基础：颜色角色、文字角色、间距、密度、焦点、层级
                         ↓
行为组件：按钮、字段、导航、选择、菜单、Dialog、Inspector、反馈
                         ↓
任务构图：阅读 / 集合 / 编辑与校对 / 分阶段执行 / 主从工作区
                         ↓
具体页面 + 固定样例 + 任务验收
```

这是职责划分，**不是要求建立五层框架或五个万能 Page 组件**。优先在现有组件和 feature 内实现，只有重复的稳定结构才抽取。

| 模式 | 适用页面 | 空间与交互原则 | 不应统一的内容 |
|---|---|---|---|
| 阅读 | 学习回答、正式笔记、错题讲解、章节材料 | 有界正文；工具与元信息退居次级；来源按需展开；长公式局部滚动 | 聊天保留追问输入，笔记不需要；错题可以有对照段落 |
| 集合 | 教材、笔记、错题、题库 | 集合名与范围→检索/筛选→条目；密度随识别任务变化；少量数据不拉伸成仪表盘 | 教材显示准备状态；错题显示下次复习；笔记显示摘要，不要求同列同高度 |
| 编辑与校对 | 笔记编辑、错题录入、候选题校对 | 编辑对象在主轴；元数据按需；修改/正式提交状态明确；校对可并排原文 | 自由写作不强制双栏；OCR 校对需要原文，不应永久折叠证据 |
| 分阶段执行 | 练习、复习、教材导入、首次配置 | 准备→执行→检查/提交→结果；阶段内内容为中心；退出能恢复时说明恢复位置 | 不画所有流程都一样的四步条；导入进度和解题进度不是同一种进度 |
| 主从工作区 | 目标与任务、设置 | 稳定的局部导航与详情；详情有独立主动作；窄窗口切换列表/详情并保留上下文 | Goal 是目标/任务关系，设置是配置分类；不共用领域状态机 |

### 5.2 全局视觉基础

延续暖中性底色、蓝色行动强调、HarmonyOS Sans、既有数学排版和主题偏好。当前没有证据支持换品牌、换字体、增加装饰性插画或删除现有主题。

| 基础 | 建议 | 判断理由 |
|---|---|---|
| 表面 | 明确导航背景、工作画布、可编辑区域、浮层四种职责；同层默认靠对齐/间距，必要时用边线 | 保留可操作区域的辨认度，不把“去卡片”变成消除全部边界 |
| 文字 | 继续区分对象标题、章节标题、阅读正文、控件、辅助信息；字号由角色确定 | 不同层级可以同字号靠位置/字重区分，不设置字号数量指标 |
| 阅读 | 现有 16px 正文、约 740px 阅读宽度作为起点；长中文检验约 40–48 个全宽字的舒适行长 | 属于试点基准，不是全部内容的硬宽度；表格、矩阵可以突破正文宽度 |
| 密度 | 初始试点：普通控件约 32–36px；密集列表约 28px；触屏和关键易误触动作保留约 44px 目标区 | 控制密度应显式选择，不能因为进入 management 就整体缩小；这些数值需在真实页面校准 |
| 间距 | 保留既有尺度，固定“组内小于组间”的关系；删除同一边缘重复 padding | 让空白说明关系，而不是机械追求每处 4px 倍数 |
| 颜色 | 操作、选择、告警、成功使用语义角色；未核验不伪装成成功；文字/形状共同表达 | 主题只改变视觉身份，不能改变操作含义或错误优先级 |
| 动效 | 保留必要的展开/状态变化反馈，遵从减少动态设置；不以页面进入动效证明质量 | 用户需要的是连续性，不是重复开场 |

字体、对比度、控件边界应验证实际渲染，包括父级 opacity、禁用态和不同背景，不能只计算 token 十六进制值。

### 5.3 共享组件体系：先收敛现有实现

| 体系 | 复用/收敛范围 | 最小契约 |
|---|---|---|
| Button / IconButton / Field | 将现有 app 类和重复字段逐步变为有类型的有限接口；不另装组件库 | intent、density、busy、disabled、label、help、error；页面不能通过祖先暗改几何 |
| Navigation / Tabs / Choice | 复用 `SelectionControls`；区分前往页面、切换面板、筛选列表、修改选项值 | 正确键盘/焦点/选中语义；外观可以同族，不必同形 |
| Dialog / Menu / Inspector | 复用现有组件和焦点处理；收敛重复教材菜单等实现 | 模态性、关闭方式、焦点回返、窄窗口行为明确；不把 Inspector 一律改成模态 |
| Async / Empty / Recovery | 复用 `AsyncState`、`WorkspaceSkeleton`、`WorkspaceActionBar` | 作用域、当前保留内容、后果、下一步；领域层继续持有真正状态 |
| Reading / Math / Source | 复用 Markdown/KaTeX、来源组件、笔记块模型 | 标题/公式/引用/表格的稳定呈现；不新建第二套生成链路 |

不创建 `UniversalLearningCard`、通用任务引擎、全局页面 JSON 渲染器或新设计工具平台。只有在两个真实消费者证明同一语义和变化轴稳定时，才提升为共享抽象；“都长得像一行”不足以共享业务组件。

### 5.4 统一的边界

**必须一致**：对象名称、范围的含义、保存状态、学习结果的含义、常用操作的语义、键盘/焦点、基础颜色与字体角色、跨页返回后的恢复行为。

**允许不同**：正文宽度、列表密度、是否并排原文、局部导航方式、主动作在顶部还是内容末端、空态位置、是否需要长期显示状态。

差异成立需要三个条件：有具体任务理由；使用既有基础角色与行为组件；有同一数据量和状态下的可读性/任务证据。新颖外观本身不是理由，像参考截图也不是理由。

“一个主动作”应解释为**一个当前决策区域具有明确的优先动作**，不能机械限制整个应用只能有一个蓝色按钮。对话输入、独立 Inspector 与正在执行的专注控制可以拥有不同作用域。

## 6. 八项重大设计决策

### D1. 从“批准页面”改为“带适用范围的参考案例”

- **解决问题**：规范合规不能产生好页面，历史参考阻止重新判断。
- **现方案为何不足**：学习和教材截图分别适合长文与管理，不覆盖写作、校对与执行；固定构图把局部成果永久化。
- **新方案为何更好**：案例记录任务、数据条件、好在哪里、不能外推什么，并由实际组件演示。新设计可替换旧案例。
- **影响页面**：全部；首先用于笔记编辑、练习准备和教材。
- **如何判断**：同一基础能够支持至少三种明显不同的有效构图，且不用增加路由专属全局覆盖；评审必须能拒绝不合适的旧参考。

### D2. 教材从维护清单转向学习入口，维护能力保留

- **解决问题**：用户看见书以后，不容易知道可以用它做什么。
- **现方案为何不足**：E02 的“重新准备”逐行显著，“设为学习范围”较弱；`/books` 装配的是 settings 的 subjects 入口。代码复用本身没错，但呈现继承了配置任务的优先级。
- **新方案为何更好**：集合主行展示书名、用途/范围和可用性，默认动作是“用这本教材学习”；进入后可查看已有目录/材料并带范围前往同一主聊天。分类、主辅关系与重新准备放入管理区；有阻断故障时恢复动作提升。导入成功提供明确去向。
- **影响页面**：教材、导入完成、范围选择、聊天、章节材料。不新建章节 AI 回答页。
- **如何判断**：从指定书到带正确范围的提问入口不超过两次有意操作；用户无需理解索引/collection 才能开始；准备失败仍能找到修复；没有偷偷扩大范围。

阶段边界：先重排已有动作。若目录浏览缺少稳定 API，先把“带教材范围进入学习”做好；目录浏览作为单列待办，不能为设计示意擅造数据或隐含批准后端重构。上述“两次”是拟议可用性目标。

### D3. 复习入口准确承诺，练习与重做共享体验语法

- **解决问题**：列表显示的工作量与按钮启动的工作量不一致，单次评价可能被理解为长期掌握。
- **现方案为何不足**：E03 同时展示到期错题和概念，主动作优先跳入错题会话；Exercises 的三档掌握文案与 Review 的本次结果文案不同。
- **新方案为何更好**：近期明确“重做到期错题”和“复习概念”的范围；有活跃会话先呈现“继续”。练习准备、作答、对照、记录结果共享位置和语义语言。长期是否合并队列，需要独立产品/领域合同，不把两套存储塞进一个新组件。
- **影响页面**：复习首页、复习会话、练习、错题详情、相关 Goal 的学习记录。
- **如何判断**：开始前能说出本次包含什么；离开后回到同一会话；参考答案不会提前泄露；提交本次结果不在界面上冒充掌握证明。改变评分映射前须核对 SM-2 与存储语义。

### D4. 笔记以文档编辑为主体，不以块数据表单为主体

- **解决问题**：阅读和编辑体验断裂，短文编辑也出现大量结构框。
- **现方案为何不足**：E05 中标题重复，标题块、段落块分别套表单，操作暴露了存储结构。
- **新方案为何更好**：保留块数据和来源；默认呈现连续文档，当前编辑块出现编辑控件，其他块保持可读；标题在文档位置直接修改，摘要/标签等退为次级信息。需要时打开原始 Markdown 或预览。笔记库提供“从会话整理”，直接选择来源，不要求用户先记住三点菜单位置。
- **影响页面**：笔记库、草稿、正式笔记编辑、生成预检、来源 Inspector。
- **如何判断**：给一篇约 1,500 字、含公式/列表/表格的样例，能改一段、检查公式、保存再打开；草稿状态与正式版本清楚；冲突保留修改。先用现有 textarea/块模型完成试点，不默认引入富文本库和格式迁移。

### D5. 错题详情按纠错逻辑组织，练习准备按决策规模构图

- **解决问题**：信息虽完整，但不利于理解错误或开始作答。
- **现方案为何不足**：E06 题干重复，短答案占整节；E04 少量准备控件被拉成宽条，视线无法形成任务中心。
- **新方案为何更好**：错题只完整展示一次题目，随后是“当时怎么做—哪里出错—怎样修正—再次验证”；窄屏纵排、宽屏适度对照。练习准备使用有界区域展示范围、数量、选题方式与开始按钮，必要时提供题目预览。
- **影响页面**：错题详情/编辑、练习准备、复习解释。
- **如何判断**：首屏能辨认题目和主要操作；短题可快速定位错因，长题不被裁剪；准备页用户能确认实际范围和题量。错题档案可看答案，但独立重做仍保持揭示门槛。

### D6. 全局壳稳定，次级空间由当前任务决定

- **解决问题**：局部导航、来源、专注等区域同时争夺空间；改一个页面容易改变别页。
- **现方案为何不足**：壳层由 `study-desk` 特例与非 `study-desk` 分支共同定义；历史、分类与详情都依赖不同覆盖。E08 的专注面板打开时确实覆盖部分工作区，但不能据此否定按需浮层本身。
- **新方案为何更好**：统一壳层职责，历史只服务会话，分类只服务教材；Inspector 临时检查，专注默认紧凑且可主动展开。根据正文可用宽度决定侧栏收起、覆盖或并排，不坚持每页同列数。
- **影响页面**：全部路由、来源、设置、专注、教材树。
- **如何判断**：1280/1024/760 宽度下主任务可读；菜单、输入和必要保存动作不被遮挡；展开/关闭返回原焦点；A→B→A 保持草稿、范围和预期滚动位置。

### D7. 状态按后果与作用域设计，而不是全部做成提示卡

- **解决问题**：同样“完成/错误/等待”的词隐藏了不同后果，状态有时抢正文、有时又不够清楚。
- **现方案为何不足**：通用 PageState/骨架不能充分表达局部失败、保存未确认、可恢复中断；“确认执行”没有直接说明业务动作。
- **新方案为何更好**：沿用现有恢复组件，在动作发生处表达对象、后果与下一步；成功以资产/结果可访问为准。按钮尽量用“保存笔记”“收录这道错题”等具体动作，必要影响保留可见。
- **影响页面**：聊天确认/缺输入、导入、笔记、练习、复习、目标、设置。
- **如何判断**：用户能区分生成完成、草稿保存、正式提交、待用户确认；局部失败不遮住已成功内容；重试不重复提交；断开不能被画成失败或完成。

### D8. 统一通过代码职责与验收实现，不通过越来越长的规范实现

- **解决问题**：Sol 局部修复用更强 CSS 选择器补齐当前截图，跨页回归继续发生。
- **现方案为何不足**：多个 token 来源、祖先决定组件尺寸、少量基准和按页面刷新检查，无法表达全部影响范围。
- **新方案为何更好**：基础值有单一所有者；组件拥有行为与几何；组合负责内容轴线；页面仅编排领域信息。改共享基础就运行所有代表模式，改局部就验证其关联消费者和跨页顺序。
- **影响页面**：全部，尤其 Portal、按需加载页面、共享表单与任务状态。
- **如何判断**：无新增未登记全局越界覆盖；共享控件在页面/Portal 的计算样式一致；变更报告能列出影响页面和对应证据；不靠刷新基准掩盖差异。

## 7. 状态与交互模式

| 状态 | 应当显示 | 应当保持 | 验收重点 |
|---|---|---|---|
| 首次无数据 | 说明可完成的第一项任务，直接进入创建/导入/选择来源 | 已选范围、已配置内容 | 新手不需要先记住别页菜单；不堆砌宣传文案 |
| 筛选无结果 | 当前筛选和清除入口 | 搜索词与筛选条件 | 不误报“没有学习资产” |
| 首次加载 | 对应页面结构的稳定占位和可感知状态 | 全局导航与页面身份 | 不把骨架截图当正文验收 |
| 刷新/后台任务 | 局部 busy 或阶段反馈 | 已读内容、输入、滚动 | 不用整页骨架替换可用结果 |
| 局部失败/离线 | 哪一部分不可用、影响、可执行恢复 | 其余成功数据与离线可读资产 | 错误不是空列表；不无故屏蔽整个页面 |
| 缺关键输入 | 缺什么、为什么影响结论、补充入口 | 已取得的内容与 task 身份 | 不伪造精确答案、不启动平行任务 |
| 待确认写入 | 对象、拟变更、必要后果、明确确认/暂不 | 用户当前学习上下文 | 点击动作与文案承诺一致 |
| 中断/恢复 | 后端已确认的状态、已有结果、恢复入口 | 同一任务/会话与草稿 | 不在停止尚未确认时显示可恢复 |
| 保存冲突 | 当前修改仍在哪里、正式版本为何未变、更安全的恢复 | 用户修改和历史版本 | 保留 E13 已有机制；不自动覆盖 |
| 完成 | 本次实际结果、资产链接/返回队列、剩余事项 | 来源和记录可追溯 | 不把“AI 完成”或“计时结束”表现成学会了 |

Anti-AI-Slop 的判断标准是**信息是否帮助理解、判断、行动或恢复**。保留“先独立作答再看答案”、OCR 校对提示、保存未确认、范围限制和失败后果。删除或改写重复状态、无作用的装饰标签、把实现机制当教学提示的文字。必要教学内容可以长，必要复杂任务可以有多个组件。

## 8. 从文档到可执行设计约束

### 8.1 代码和静态检查能负责什么

1. **Token 所有权**：保留主题注册表；生成默认 CSS 或由同一数据源导出，避免人工维护重复色值。排版、间距、密度各有唯一来源，旧变量先做兼容映射，不一次替换全库。
2. **完整引用检查**：扩展现有检查到所有实际应用样式和主题输入，识别定义、引用、合法局部变量与 fallback；不能只扫描 `index.css`，也不能把运行时几何值误报成非法设计 token。
3. **组件接口**：Button/Field 等只开放必要 variant。CSS 静态检查约束组件几何的越界重写、新增无作用域选择器、无登记的颜色/字号字面量。光学校正、图像几何、KaTeX 与动态位置有明确豁免。
4. **职责边界**：feature CSS 不修改别的 feature 或全局壳；共享组件不感知具体路由；样式导入图可定位消费者。存量问题登记，新增变更逐步收紧，不以全库整改阻断当前工作。
5. **语义契约**：检查字段持久标签、图标按钮可访问名称、禁用与 busy、tabs/panels 关联；交互行为交由运行测试。旧源码字符串断言逐步替换，保留其所保护的真实功能。

不新增“页面最多几个卡片”“只能几种字号”“不得出现某个词”“全页只准一个主按钮”等容易量化但错误的指标。

### 8.2 自动化渲染与交互负责什么

- 相同语义控件在页面、Dialog、Inspector 中的计算字号、高度、焦点、选中态一致；显式密度变体可不同。
- 重要内容及动作可见且可达，包含真实滚动末端；页面整体不横向溢出，长公式/表格允许局部滚动。
- A→笔记→A、A→教材→A、打开/关闭设置的样式与上下文连续性。
- 未保存、局部失败、重复点击、恢复、键盘、焦点回返等真实交互合同。
- 截图差异用于提示变化；按渲染环境分基准，不能把跨平台字体差异误当页面失败。

### 8.3 必须留给设计评审的判断

- 用户能否理解当前页面的主要任务和下一步。
- 页面视觉重心、分组和密度是否适合内容与操作频率。
- 例题、公式、来源、反馈是否帮助学习，而不是相互竞争。
- 哪些信息应持续显示、按需显示或重新组织。
- 新模式是否值得进入共享系统，还是仅适合当前领域。

设计评审不能仅输出“看起来不错”。应引用具体画面与任务，说明保留、取舍和成功条件。AI 可辅助检查与给出判断，但不能把模型间的一致意见称为用户可用性证据。

### 8.4 Sol 如何执行局部任务而不破坏整体

每项任务只需一份短变更说明，放在现有任务/PR 中，不新建审批平台：

| 必要信息 | 例子 |
|---|---|
| 用户任务与模式 | 在笔记中修正一条公式；文档编辑模式 |
| 改动范围 | DraftWorkspace、NoteBlocks；是否触及共享 Field/Token |
| 必须保持 | 来源、草稿自动保存、正式版本 CAS、退出恢复 |
| 影响清单 | 笔记编辑/阅读；若改 Field，再覆盖设置、候选校对、教材导入 |
| 证据 | 原图/改后图、视口/主题/构建身份、交互结果、未验证项 |

执行时先确认影响范围，再落地一个完整试点。局部页面改动不准顺便修改全局视觉角色；若确实需要改变共享角色，就把任务显式升级为共享变更并扩展验收。发现既有模式不适合时可以提出替换方案，不要求为了规范牺牲页面质量。

新页面从最接近的**任务示例**继承，复制组合而不是复制任意业务页面；领域状态仍由既有 hooks/services 提供。试点成功后，才将稳定的模式反向写入组件 API、样例和少量理由说明，并移除被替代的旧规则。一次新增规则应替代重复规则或解释一个真实新决策，不按页面不断附加例外。

## 9. 全局视觉回归与验收机制

### 复用已有设施，补齐缺口

继续使用 `qa-pages.mjs`、`qa-visual-compare.py`、隔离 E2E、Electron QA 与 Visual Review Board。不要求改用新平台或立刻引入 Storybook。

当前固定基准是 learning/exercises 的四种宽度共八张。`qa-pages` 的 PASS 主要表明没有匹配页面加载失败边界，并另外记录/检查页面宽度；这不是审美通过。其 `console` 错误记录与最终按 `error` 字段失败的逻辑也应核对，避免记录了错误却未进入门槛。改造前先区分产品错误与缺失 fixture 端点。

### 三层验收

| 层 | 覆盖 | 触发条件 | 通过含义 |
|---|---|---|---|
| 组件/基础 | 常用控件状态、文字角色、主题、Portal、焦点与键盘 | 组件/token/全局样式变更 | 基础没有明显退化，不代表页面设计优秀 |
| 页面/组合 | 五种模式的代表页＋本次所有受影响页面；首屏和关键末端 | 任何用户界面变更 | 构图、可读性与状态呈现符合本次明确设计 |
| 学习旅程 | 教材→提问→来源→笔记；题库→作答→错题→重做；目标/专注跨页恢复 | 相关流程变更、阶段发布 | 任务可完成、状态与记录准确，不代表模型答案准确率 |

### 样例矩阵

数据规模覆盖空、少量、常见多条和压力样例；例如 1/20/200 条资产、长中文书名、1,500 字笔记、多轮长回答、大矩阵、缺失参考答案、混合教材准备状态。这些是测试输入，不是限制产品容量。

窗口以 Electron 为主：1280×820、1024×768、760×820；宽屏 1600×1000 验证正文不会无限拉伸；390 作为已有移动支持的防退化检查，不能代替桌面验收。默认主题跑完整组合，其他主题跑基础组件及跨模式代表页。加入文字缩放与键盘场景，按风险选择而非全量笛卡尔积。

冻结截图时钟、数据、字体、缩放、滚动位置和动画；等待指定正文和关键状态，不能只等 networkidle。每组保存 commit、dirty diff 摘要/指纹、构建 ID、fixture 版本、平台、视口、主题、route/state。来源不同的旧截图可以用于诊断，不能混装成当前发布通过证据。

### 通过与更新基准

- 自动检查失败必须解释并解决；预期视觉变化进入人工确认，不能自动重录基准。
- 总像素阈值保留为提示，增加关键区域对比与 DOM 可达性检查，避免按钮消失只占很少像素却被总量阈值掩盖。
- 每次共享变更至少检查一个阅读、一个集合、一个编辑/校对、一个执行、一个主从页面，以及受影响浮层；变更影响清单比固定抽样优先。
- 设计通过需同时有任务理由、原图可读性判断、相关交互证据。模糊时保留“待验证”，不写“全产品通过”。
- 将已有离线截图/行为检查接入 CI。当前 CI 有测试/lint/build，但没有全局视觉基准门槛；push 分支只列 main/master，需补日常 `Texa_MacOS` 集成触发。Windows 共享界面需要对应环境验证；macOS 原生窗口与打包生命周期单列，不借浏览器成绩替代。

建议在首轮试点增加小规模任务验证：邀请 3–5 名目标学习者做同一组任务，记录首次动作、完成、回退、误解和恢复。对比旧版与候选版，交错顺序以减少学习效应。小样本用来找问题，不宣称统计显著提升；没有参与者时，明确保留专家审计等级。

## 10. 实施计划与 Sol 任务边界

这是后续任务建议，不是本轮已授权的代码改造。先定清楚用户可见行为，再实施；数据库/运行时/依赖或高风险架构变更需单独评估。

| 阶段 | 实际交付 | 退出条件 |
|---|---|---|
| 0 当前证据与语义冻结 | 在当前工作树采集完整代表集，记录未提交修改；梳理复习入口、评分、教材动作和笔记入口合同 | 不再用旧截图猜测当前效果；明确哪些只是布局，哪些涉及产品流程 |
| 1 三个完整试点 | 教材入口、笔记编辑、练习准备；同时澄清复习主按钮覆盖范围 | 每个试点有 populated/empty/error/恢复设计，真实任务可走通；不先铺开全站 tokens 重构 |
| 2 提炼可执行系统 | 从试点提炼基础 token 所有权、Button/Field 密度与五类组合示例；清理相应旧覆盖，接入回归 | 同一共享实现用于不同模式，没有依赖导入顺序的意外变化 |
| 3 有针对性推广 | 错题详情、复习执行、候选校对、目标局部层级、其他集合和浮层 | 受影响页面与学习旅程逐项验收，移除被替代模式；不要求每页重画 |
| 4 集成与持续维护 | 合入 `Texa_MacOS`，当前 Electron 构建复验，版本记录与基准更新 | 发布身份可追踪，旧路径/数据/恢复合同保持；跨平台未测项明确列出 |

### 可直接拆给 Sol 的执行包

| 编号 | 执行内容与主要位置 | 可以做 | 不得自行扩大 | 验收 |
|---|---|---|---|---|
| S0 | QA 身份与覆盖：现有 scripts、docs/qa、CI | 补元信息、场景和失败门槛；复用离线 fixtures | 不触碰真实数据、不付费调用模型、不把新截图自动批准 | 当前五种模式证据可定位；有效内容/已知 fixture 缺口分开 |
| S1 | 教材入口：LibraryWorkbench、SystemHealth 装配、BooksPage | 调整默认动作和信息主次；用既有能力带范围进入学习 | 不新增第二条回答链、不改索引发布/主辅检索语义、不擅做目录 API | D2 的入口、范围、失败恢复任务 |
| S2 | 笔记编辑与来源入口：DraftWorkspace、NoteBlocks、NotesPage、NotePreflight | 连续文档编辑、元信息后置、从会话整理入口 | 不迁移存储格式、不引入富文本依赖、不取消明确保存/来源/CAS | 长文公式编辑、冲突、保存再读与返回恢复 |
| S3 | 练习与复习：ExercisesPage、LearningPage、ReviewSessionPage | 准备布局、准确按钮承诺、恢复入口与揭示层级 | 不直接合并会话状态机、不改评分→掌握/SM-2 映射 | 含错题+概念的混合首页；开始/离开/继续/提交一致 |
| S4 | 共享控件与样式：ui、theme、index、layouts | 从批准试点抽取有限 variants；迁移消费者并移除重复规则 | 不一次重写全部 CSS、不通过更强祖先选择器掩盖冲突、不改用户主题 ID | 五种模式＋Portal＋A→B→A 回归 |
| S5 | 错题与候选校对：MistakesPage、MistakePresentation、习题候选组件 | 去重复题干、纠错对照、原文与编辑的空间关系 | 不把 OCR 自动当最终题干、不删除解释/来源/确认门槛 | 短题/长题/图片题、独立重做答案门槛和候选入库 |
| S6 | 壳层、目标和集成：MainLayout、AppRail、GoalsPage、FocusPanel | 在已定构图下收敛壳层，去重复筛选，优化空间与焦点 | 不重做 Goal/task/focus 模型，不改变暂停/结束/完成的后端含义 | 运行中跨页、窄桌面、浮层展开、保存与关闭路径 |

执行顺序：S0 → S1/S2/S3 的完整试点 → S4 → S5/S6。这里的并列表示可独立规划，不要求启用多 Agent；也不要求为每项引入新的审批文档。

Principal Product Designer 应负责试点的任务结构、重大模式替换和跨页面取舍；Sol 负责在边界内完整实现、补齐状态、提供影响清单及证据，并有责任指出设计无法满足领域合同的地方。不能把角色简化成“Astra 给规则，Sol 调 CSS”。

## 11. 最终建议

先把教材入口、笔记编辑和练习准备设计成三种真正适合其任务的页面，再从这些页面提炼共享语言。以学习回答和笔记阅读保留已有优势，用错题与复习验证教学闭环，用状态恢复证明系统可靠。

Texa 需要统一的是操作和信息的含义、基础视觉语言与可预测的行为；需要保留差异的是阅读、写作、校对和执行所需的空间结构。设计体系的价值应以这些任务是否更自然、更清晰、更可靠来判断。
