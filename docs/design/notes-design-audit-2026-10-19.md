# 笔记设计与取证审计

日期：2026-10-19。审查对象：[Astra brief](astra-notes-design-review-brief-2026-10-19.md)及其引用证据、当前 `Texa_MacOS` 工作树（HEAD `1dc9adc`）。

结论：brief 足以支持其限定范围内的试点收尾，但不能作为笔记编辑体验完整验收。建议保留当前块数据结构、MathLive 和草稿/正式版本分离机制，优先补齐删除恢复、窄窗阅读样式、版本状态和跨模式位置连续性，再做编辑层级精简。没有证据要求替换编辑器或引入新依赖。

本次只新增审计报告；未修改产品、原始 brief 或旧验收记录，未启动远端模型调用。文档中的实施建议没有被当作用户授权。本次使用 `texa-ui-system`，未委派子代理。

## 审查依据与边界

- 独立计算 brief、6 个笔记源码、3 个取证脚本、3 个试点产品文件的 SHA-256：13/13 与清单一致。brief 的本地 Markdown 链接全部存在。
- 查看 8 张已有 Electron 截图，覆盖同一草稿的编辑/阅读/聚焦、1024px 编辑、760px 编辑/阅读、矩阵聚焦和正式版本冲突。
- 阅读原始测量 JSON、检查断言、保存编排与相关样式；核对前端 8 项、后端 47 项测试日志和构建日志。这些是既有运行结果，本次没有重新执行 Electron、测试或构建。
- 下文区分截图/既有测量、源码可确定行为、设计判断。没有真实用户效率、误触率、完整辅助技术或跨平台验收数据。

## 按优先级排序的发现

### 1. P2：删除块直接自动保存，缺少恢复入口

证据：[NoteBlocks.tsx:38](../../frontend/src/features/notes/NoteBlocks.tsx#L38) 点击删除直接过滤数组；[autosave.ts:44](../../frontend/src/features/notes/autosave.ts#L44) 把该变更纳入 800ms debounce 自动保存。编辑器未提供块删除撤销；[service.py:167](../../backend/services/session_notes/service.py#L167) 更新当前草稿，[session_notes.py:107](../../memory/session_notes.py#L107) 的存储写入覆盖当前草稿文档。

触发情形：用户删除包含尚未正式保存的新内容的块，随后自动保存成功。正式版本历史没有这部分新内容，输入框原生撤销也不能恢复被 React 删除的块。只禁止删除最后一块不能保护这一场景。此项为源码审计结论，本次未执行误删复现。

建议：提供明确的块级撤销，恢复完整块内容、稳定 ID、来源关联及原位置，并走原有 CAS writer。优先支持可恢复操作，不必给每次删除增加确认弹窗。验收须包含“新内容—删除—自动保存完成—撤销”，不能只用正式版本历史代替草稿恢复。

### 2. P2：窄窗阅读正文被全局 compact 样式缩小，brief 缺少该差异

证据：[MainLayout.tsx:27](../../frontend/src/layouts/MainLayout.tsx#L27) 在宽度 ≤760px 时启用 compact；[index.css:3493](../../frontend/src/index.css#L3493) 对 `.app-shell[data-layout="compact"] .markdown-body` 指定 13px，并对其中段落指定 1.62 行高。该选择器优先级高于 [notes.css:15](../../frontend/src/features/notes/notes.css#L15) 的阅读角色。Markdown 渲染根节点同时有 `markdown-body` 和 `learning-reading-content`。

[760px 阅读截图](../qa/ui-pilot-closeout-2026-10-19/notes/2026-10-19T07-39-34.130Z/760-preview-top.png) 显示正文比摘要明显更小、更密。brief 引用的 16px/30.4px computed style 来自 1280px 同草稿测量；没有对应 760px computed style 记录。源码推导的窄窗普通段落为 13px/21.06px，不应把这个推导值伪装成本次实测。

影响：窄窗正文与摘要、公式比例失衡；“页面未横向溢出”没有覆盖阅读角色是否被全局规则覆盖。

建议：让笔记阅读角色在三个目标尺寸下保持明确、经过审查的字号和行距；补测实际正文段落、列表及公式的 computed style。brief 的 16px 测量应注明窗口尺寸。

### 3. P2：≤1024px 隐藏的不只是版本元数据，还包括历史只读与归档状态

证据：[notes.css:60](../../frontend/src/features/notes/notes.css#L60) 对 `.note-header-state` 使用 `display:none`；[NoteDetailPage.tsx:15](../../frontend/src/pages/NoteDetailPage.tsx#L15) 把“历史版本 N · 只读”和“已归档”放在这个元素内。

影响：用户打开历史链接或归档笔记时，首屏缺少直接的状态说明。历史页仍有“当前版本”链接，归档页仍有“恢复”按钮，不能表述成完全无提示；但它们不能等价替代明确状态。“笔记信息”折叠区也不能承担首屏只读辨识。`display:none` 同时使该状态离开可访问性树。

建议：窄窗保留“历史版本 N · 只读”或“已归档”的简短文本，优先压缩普通已保存提示及次要操作。验收 1024/760px 的历史、归档和当前版本，而不只检查编辑草稿。

### 4. P2：编辑与阅读切换缺少内容锚点，影响校对流程

证据：[DraftWorkspace.tsx:87](../../frontend/src/features/notes/DraftWorkspace.tsx#L87) 只切换 `editing`；[同草稿测量](../qa/ui-pilot-closeout-2026-10-19/notes-detail/2026-10-19T07-44-39.001Z/results.json) 显示编辑与阅读都为 scrollTop 829.5，却对应不同内容，另一次切回编辑时为 0。

判断：这不是此次 Composer 试点引入的回归，但属于实际工作流缺口。修改公式后查看渲染、再回原处继续编辑是笔记校对的合理任务，应把同块连续性列为下一阶段交互合同。

建议：以已有 `block_id` 保存内容位置，必要时补块内偏移及编辑选区；切换后让同一块可见。焦点是否自动返回输入框应按键盘路径明确设计，不宜为了恢复滚动强制抢焦点。不要把“保持相同像素 scrollTop”作为通过标准。

### 5. P3 / 设计判断：编辑页面的控件层级超过内容编辑所需

证据：[编辑开头](../qa/ui-pilot-closeout-2026-10-19/notes-detail/2026-10-19T07-44-39.001Z/same-draft-edit-top.png) 同时呈现文档 H1 与标题输入；每块有外框、类型/序号、操作行、字段标签及输入边界。测量中单行标题块约 209px 高，标题和长段落均从 85px textarea 起步；第 4 块 clientHeight 83px、scrollHeight 154px。

判断：应局部调整。短标题占用过多空间，长段落又无法完整显示；这一组合妨碍同时核对段落与相邻公式。尚无证据量化效率损失或证明已发生误操作。

建议：编辑标题采用单一可编辑呈现；标题字段按短内容适配，正文按内容增高并为极长内容设置合理上限；降低非当前块外框和工具的视觉权重，保留清晰的当前编辑块和单一焦点指示。标签可减少视觉重复，但 accessible name、类型辨识和键盘操作能力必须保留。不要直接把所有工具改成仅鼠标 hover 可见。

## 对 brief 本身的修订意见

1. **区分行为合同与当前实现。** 第 4 节把“块工具常驻，普通 Tab 顺序”列为必须保留，第 5 节却又要求判断工具何时隐藏。应保留操作能力、可发现性、禁用边界与键盘可达性；常驻外观和具体焦点组织属于可审查实现，不能预先冻结。
2. **限定字号测量适用范围。** 16px/30.4px、740px 来自 1280px 阅读测量，不能代替全部尺寸的有效样式。应补充发现 2 所述的 compact 覆盖。
3. **把 10/10、3/3 的含义写清楚。** 10 项包含 Electron preload、三个宽度的 document 横向溢出、自动保存/正式保存、历史编辑按钮、冲突和 renderer error。3 项仅为 preload、窄窗 document 横向溢出、renderer error。它们不是 13 个完整编辑场景，也未断言跨模式同块连续性、删除撤销、Tab 路径或窄窗状态可辨识。brief 已避免宣称完整验收，建议继续保持这一边界。
4. **119px 标题栏应调整，但不等同于按钮裁切故障。** 高度占 820px 窗口约 14.5%，截图中标题/返回/状态分散在左侧三行，主动作分布在右侧两行。建议设计明确的两行布局并保留必要状态；不能为了固定成 48px 而隐藏历史/冲突状态。
5. **构建警告应完整记录。** 保存的 build 日志还有大于 500kB 的 chunk 提示。它不使构建失败，也不直接阻断此次 UI 试点，但 brief 末尾只提 Starlette warning，容易遗漏构建侧信息。

## 对提交设计判断问题的回答

| 问题 | 审计判断 | 必须保留 |
|---|---|---|
| 层级是否过多 | 是，建议局部精简，优先消除标题重复、统一高度和双层容器的无效占用 | 输入名称、块类型、公式说明、保存状态、可见焦点 |
| 是否区分当前与非当前块 | 是，当前块应更清楚，非当前块应让正文优先 | 键盘与触控可达，不能只有鼠标悬停才能发现操作 |
| 是否明确内容位置连续性 | 是，列为下一阶段交互验收项 | 同一草稿、稳定 block_id、现有保存与冲突权威 |
| 是否调整窄窗标题栏 | 是，连同正文样式和版本状态一起审查 | 保存/返回入口、历史只读/归档/冲突语义、macOS 原生窗口安全区域 |

## 建议的实施与验收顺序

先处理删除恢复、窄窗正文/版本状态，再处理按块切换连续性，最后精简编辑层级与标题栏。均优先在现有组件和样式内完成；本报告不是实施授权。

后续验收沿用 1280×820、1024×768、760×820，同一草稿同一内容对照；补充删除撤销、正文有效字号、历史/归档状态、长段落与公式校对、键盘顺序及焦点恢复。继续验证自动保存不发布正式版本、保存前 flush、冲突不覆盖、退出失败保留文字。旧测试通过不能替代这些新增交互断言。
