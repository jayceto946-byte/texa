# Texa Icon System — 设计评审与建议

2026-10-30。以 [设计板](http://127.0.0.1:5173/icon-design.html) 同组 20 个语义、16/20/24/32px、产品语境和现有五主题评审。评分是设计者的初步判断，不是用户识别率；所有方向都保留，不代表正式选型或发布验收。

## 初版加权评估（本轮改稿前）

每项 1–5 分，5 为最佳；总分 = Σ（单项分 / 5 × 权重）。

| 维度 | 权重 | A | B | C | 具体视觉依据 |
|---|---:|---:|---:|---:|---|
| Visual Consistency | 25% | 4.5 | 3.5 | 4.5 | A 统一线框，C 页脊/段落语法一致；B 实心删除/发送比搜索、复制更重 |
| Semantic Clarity | 25% | 4.5 | 4 | 3.5 | A 放大镜、铅笔、旗帜与检查括号熟悉；C 检索/抽取/执行在无文字时容易混淆 |
| Distinctiveness | 20% | 2.5 | 4 | 4.5 | A 接近通用专业工具；B 的标题带和不对称实心有区别；C 把来源页边和段落操作关联，符合教材系统 |
| Small-size Legibility | 15% | 4 | 3.5 | 3.5 | A 简单动作空隙大；B 删除形成重色块；C 已对五个复杂图标减笔，但窄书脊仍有密度风险 |
| Scalability | 10% | 4.5 | 3.5 | 4 | A 新增成熟隐喻容易；B 每枚需重新平衡实心比例；C 适合学习资产，通用操作须克制应用母题 |
| Implementation Quality | 5% | 4.5 | 4.5 | 4.5 | 均为简短 SVG path / currentColor；React 与静态导出共用几何。仍需生产调用点与 1× 屏幕验收 |
| **加权总分 /100** | **100%** | **80.5** | **75.5** | **81.0** | C 与 A 接近，不能把 0.5 分差当作识别优势的证据 |

## 三方向取舍

**A — Precision Geometry。** 识别效率与扩展成本最好。搜索/返回与已有用户习惯兼容；教材打开、步骤组合、验证括号比当前毕业帽/脑回路更切题。缺点是独立视觉身份弱，部分题库横线偏多。适合作为所有通用操作的基础。

**B — Editorial Minimalism。** 书籍的实心书脊、题目的标题带、复制的前后层级清楚，在单枚静态图上轮廓鲜明。与编辑设计契合，但按钮同时出现时，实心纸飞机和删除桶占视觉优先级过高；必须逐枚调整填充比例，后续维护成本较高。不建议整套直接迁移。

**C — Texa Original。** 页边索引强调教材定位和段落操作，避免 AI 星芒、轨道、脑形模板。教材、题库、错题、笔记有共享来源感，旗帜与对话框避免全套同形。主要缺陷是检索/抽取/受控执行的箭头都出现在右侧，16px 下仅靠内部线段辨别仍不够稳。知识抽取和受控执行必须保留文字；受控执行不应成为通用机器人标志。

## 当前方向：深化 A

用户本轮明确偏好 A，同时指出书页与加号/勾选直接叠加的层级问题。此前“C 教材语法 + A 通用操作”的设计建议由此更新：以 A 的精密线框为主，优先处理复合图形，B/C 只保留为对照。不据偏好反向修改初版评分；上表不代表当前改稿的再评分。

最新一轮按用户逐项反馈细调：教材检索恢复初版；命题保留原页框与题干，主要将加号缩小并收进框内；验证保留括号和内容短线，将勾选缩小放在右下留白；知识抽取保留上一轮新版；错题改为三行细点，末行末尾放整体缩小 50% 的叉号，底部留空。

设计板默认 A，以“初版参考 / 当前采用”比较 16/24/32px。修订目标是动作与内容的比例，不是删除所有正文或禁止任何外置图形。检索两列相同是有意恢复初稿。用户随后授权进入软件，A 已通过统一语义组件接入对应位置；原型评分仍只代表初版探索。

本轮类型检查与定向 ESLint 通过；实际审阅窄窗口的三尺寸对照，截图见 `previews/a-detail-refinement.png`。沿用既有交互验证，不重复整套业务测试；未做 Windows 栅格实测。上一轮更彻底的单一符号版本可参见 `previews/a-hierarchy-revision.png`，不再作为当前采用方案。

## 预计迁移范围与风险

库存为 216 个源文件的扫描结果，79 个实际 Lucide 图形名称，216 组图标/文件引用、287 个静态引用位置。这里是源码频次，不是使用频率；别名、动态映射与重复 JSX 会影响计数，不能据此给出工期承诺。

| 批次 | 实际组件/目录 | 要处理的边界 |
|---|---|---|
| 产品身份 | AppRail、ScopeSelector、LibraryWorkbench、LearningPage | 导航与范围语义分开；现有 16px/1.6 CSS 覆写必须定点处理；导航顺序和路由不变 |
| 学习输入与证据 | ChatPage、ChatMessage、ExecutionTrace、SourceGroupList、visual-learning、math-input | 附件 📎 有历史文本解析契约；验证图形不是数学验证成功的证明；数学输入符号保留文字 |
| 学习资产与操作 | exercises、notes、focus、GoalsPage、MistakesPage | 合并同义搜索/刷新/编辑入口；保留按钮可访问名称、CAS/异步状态和用户文字 |
| 通用壳层与设置 | DesktopTitleBar、AsyncState、OverflowMenu、ScrollableSelect、settings | Windows 还原与复制分开语义；原生 macOS 按钮不改；loading 不能被静态状态图标替换 |

正式迁移涉及现有 216 组图标/文件组合（不是 216 个组件），加 CSS select 下拉箭头与消息附件文本兼容。20 个样本是探索集，剩余约 59 个导入图形名称仍需在确定语法后逐类设计或保留。不要把原型候选表当成全集替换表。

维护风险：当前 SVG 导出与 React 由同一几何生成，但提交时仍须同步静态导出；24px SVG 被外层 CSS 改成 16px 会跳过减笔；miter 转角、实心比例、浏览器抗锯齿在 Windows 100%/125% 可能不同；单色图标仍要由文字解释状态，不能仅靠主题色区分。未新增依赖、字体或配色。

- `npm run build`：TypeScript 与生产 Vite 构建通过；保留项目已有的大 chunk 提示。独立设计板不进入生产输出。
- 设计目录定向 ESLint：通过。修复了初版章节链接中的全角空格 lint 问题。
- 一次隔离 Electron 检查覆盖 20×3 候选、层级筛选、选择联动、16px 减笔、SVG 下载、输入启用/发送反馈和本地主题隔离；视觉修订后针对同一设计板复核。没有 API 请求，无真实模型或数据库写入。
- Electron 窗口内容区域按 1280×820、1024×768、760×820 检查页面溢出；五主题均渲染。对比审阅了专属图标、尺寸区、窄屏语境与主题截图。
- 原有 ui-refactor-preview 入口本次加载为空；没有将其计为现有业务界面实测。使用 `artifacts/study-desk/learning-final-type.png` 批准参考与现行样式核对阅读画布和控件层级；设计板的产品语境是隔离展示装配。
- 本次未测试 Windows 安装包、真实 Windows 1×/125% 栅格、深色模式（当前没有该主题）或用户无标签识别。无全局迁移，无 commit/push。

重现隔离检查：在本地 Vite 已启动时，于仓库根运行 `./desktop/node_modules/.bin/electron scripts/design/verify-icon-board.cjs`。截图和机器可读结果默认写入 `/tmp/texa-icon-board-qa/`；这是原型 QA，不是产品业务端到端验收。
