# 会话置顶、归档与可恢复删除：已批准的实施范围

本提案配套 `desktop-ui-refactor-astra-plan-2026-10-03.md` 第6节。用户于 2026-10-03 明确批准继续实施；实施与验收见 `desktop-ui-refactor-followup-2026-10-03.md`。现有会话权威内容位于 `PROGRESS_PATH/conversations/_conversation_events.db`，JSON只是最近窗口投影；当前 API 没有生命周期元数据。

## 建议批准的具体改动

1. 在现有会话 SQLite 库新增独立的会话管理元数据与操作回执表，保存 conversation_id、pinned、active/archived/trashed、revision、更新时间及原状态。消息、Ledger、冻结笔记来源和现有事件保持原样。不要将界面管理事件混入消息 event log，避免改变 Resolver 的近期事件/并发判断。
2. 旧会话无需重写正文：缺少管理元数据视为未置顶、active；第一次管理操作事务创建默认行。新增表/版本登记属于存储合同扩展，在本次明确批准后实施，并先验证备份/恢复与升级回退。
3. 应用服务提供幂等的置顶/取消置顶、归档/恢复、移到回收站/恢复。请求带 operation_id、expected_revision；旧 revision 返回明确冲突，重复同一操作返回原回执。Router仅做协议转换。
4. 历史增加正常、归档、回收站视图；默认列表不显示 archived/trashed，置顶排在最近会话前。增加稳定游标分页，避免只在最近80条中查找置顶会话。现有消息历史游标及旧列表调用保持兼容。
5. 三点菜单“删除”初始仅移入回收站，确认文案说明可以恢复，且不会删除已保存笔记、错题和独立Goal。提供撤销和回收站恢复；不设自动过期清理、不提供永久删除、不执行级联清理。
6. 置顶只是导航优先级，不启动Goal。归档/回收站不能暗中中断执行；服务需读取真实会话相关任务，并对运行中、等待输入/确认或可恢复任务给出明确门槛。需要停止时引导已有停止流程，后端确认后再操作；并发准入与管理动作共用现有栅栏/锁合同，不能只靠前端按钮禁用。此项实施前补齐实际Runtime集成核对。
7. 回收站会话通过用户明确恢复后才能继续提问；恢复回到先前的 active/archived 状态并更新revision。已有正式笔记保留冻结片段可读，回到原会话时提示其归档/回收站状态，不从新索引补充旧来源。

## 影响、验证与回退

- 影响文件范围：会话存储入口、独立会话管理service/API/schema、Sidebar feature状态、备份与storage manifest；不会迁移教材索引或改变模型配置。
- 使用临时SQLite先验证缺省旧数据、幂等、CAS冲突、全量列表分页、归档/回收站恢复、进程重启、并发运行门槛、独立资产仍可读，再演练备份恢复。
- 新管理功能关闭时仍能读取全部原消息；正式回退需兼容保留元数据，新表不被旧版本删除。不会以回退为由抹去管理状态或学习内容。
- 本阶段不包括永久删除、小模型选择整理侧重、Goal对话身份合并、开放Agent Loop或付费Answer Eval。

本次已批准对象为以上可恢复的管理能力和必要存储/API扩展。仓库 `AGENTS.md` 明确要求“涉及架构、数据迁移、依赖重装、删除数据等高风险操作时，需要征得用户同意”，因此在已有UI阶段完成后提交这份具体方案供用户批准。实施采用真实持久化管理状态，不把 localStorage 隐藏当作完成。
