## 3. D02：疑问词被当成实体的一部分

### 已确认根因

实际请求 `a87eb942c6a144bd8ec808ef1f130c3d`：

- 问句为“什么是电阻式传感器？”，Resolver 正常 `continue`，intent=`definition`。
- 运行提示词已是 `refined-teaching-v2-2026-10-04`，因此不能只归因于未重启旧后端。
- 检索有候选，但 support=`insufficient`，assembly=`grounded_refusal_no_generation`，未调用回答模型生成。
- 候选中包含“4.1 应变式电阻传感器”，同时有一般分类、应用及电容等旁支。

`graph/retrieval_node.py::_extract_query_focus` 从句首推断实体时，正则允许“什么是”进入主题；填充词只包含“是什么”，没有等价处理“什么是”。只读对照：

| 输入 | 主题 / 焦点提取 | 生产词法路径结果 |
| --- | --- | --- |
| 什么是电阻式传感器？ | 主题=`什么是电阻式传感器` | insufficient，最终证据 0 条 |
| 电阻式传感器是什么？ | 主题=`电阻式传感器` | supported，最终证据 9 条 |
| 原问句，显式提供主题“电阻式传感器” | 主题正确，但焦点残留=`什么` | 说明只修主题仍有遗漏 |

### 解决方案

1. 在确定性问题分析中识别“什么是 X / X 是什么 / 请解释 X / X 的定义”等定义表达，把疑问结构与实体分开。仅清理明确的句法位置，不全局删除实体内部字符；原始问题与持久化内容不变。
2. 统一检索查询、主题/焦点支持度使用的实体边界，避免 Resolver 已识别正确实体、support gate 又自由推断出另一个实体。理解接口保持默认 off；该确定性错误无需通过启用理解模型来解决。
3. 定义问题优先选中同对象的定义/原理说明。最终证据不应由一般分类和应用片段主导；“应变式电阻传感器”仅支持其中一个分支时，回答要保留教材实际范围，不能等同于全部电阻式传感器。
4. 保留现有范围、型号、引用和支持度门槛；修复输入语义错误，不下调门槛。缺少定义支持时披露本轮缺口，并保留用户显式选择通用回答的入口。
5. 拒答诊断增加不含正文的 reason、实体/维度计数、候选/过滤/最终证据数量及规则版本。明确区分检索失败、语义不匹配和生成失败。

**验收：**上述同义问句解析一致；真实教材相关定义/原理进入最终 EvidencePack；电容/压电、不存在对象、错误型号与指定章节负向用例仍守住边界。后续真实模型回答需人工检查定义、工作原理及适用范围，不能只按 supported 判成功。

### D03–D06 的补验收

- D02 按定义、列举、比较、原理分别建立至少一个有教材预期的样本；与 D03 的推导、应用计算、跨章组成七类独立结果。
- D03 核对公式条件、单位和关键步骤；适合受限数学工具的计算执行确定性校验。缺关键参数时不能输出精确数值。
- D04 分别验章节讲解和总结；`chapter` 先于正文，阶段事件不覆盖正文，长内容及公式可读。
- D05 每个引用核对实际书/版本/片段和对应结论，旧索引引用不可按标题静默重绑。
- D06 保留已通过的状态与执行详情检查，新增“流结束但问题未回答”的语义验收；不把长度、引用合法或结构检查描述成答案准确率。

## 4. F01：确定为 invalid_document，具体结构失败点已丢失

### 已确认事实与未知项

同一冻结来源 `snapshot_47c3f95f858b42119764da7c401fa613` 的三次任务均失败，错误码都是 `invalid_document`；未发布 candidate。来源保留，包含一个完整 turn、两条消息、六条证据及三个章节锚点。

本地固定 32000 context / 8000 output 配置的调用前检查可正常到达 organize 阶段：两条输入消息，payload 约 11.6 KB。这只说明该配置下来源可形成单批输入，不证明当时模型配置或返回值满足预算。不能把问题归因于“只读了最后一条回答”或来源已丢失。

`backend/services/session_notes/generation.py::decode_result` 的严格 JSON 检查，以及 `validation.py::validate_document` 的标题、字段、块类型、长度等检查都可能抛 `invalid_document`。`jobs.py` 只保存统一代码；前端 `GenerationWorkspace` 又统一显示失败文案。**现有证据无法进一步区分 JSON 不合法、输出截断、未知字段或块结构不符，不能选一个猜测当根因。**

### 解决方案

1. 先补脱敏错误分类：`json_decode_failed`、`output_truncated`（须有结束原因等依据）、`document_schema_failed`、`invalid_source_ref`、`no_learning_content`、`model_unavailable`、`transport_timeout` 与 `candidate_receipt_mismatch`。错误码、阶段、字段路径、输出长度、模型/提示词版本写入现有任务元数据；不保存原始响应、教材/会话正文、端点或密钥。
2. 模型调用保留 finish reason、usage 和内容类型的安全元数据；超时/断流不能统一算结构失败。UI 按错误类别给出有用动作：缩小选区、调整配置、从同一来源重试、手动整理，保留来源与可编辑内容。
3. 生成提示词与校验器使用同一结构合同：合法枚举、块字段、标题/摘要上限、章节锚点规则及 JSON 内 LaTeX 反斜杠转义。对已冻结章节采用服务端分配的有限 token，禁止模型伪造 ID；未提供锚点时可以留空。
4. 若配置的 transport 已声明且实际支持结构化输出能力，可在 `llm` 角色工厂内使用；未声明时继续严格 JSON 路径，不在笔记服务硬编码供应商。该能力需先核对本地 registry 与 transport 合同，再确定实现范围。
5. 本地只做无语义变更的解析兼容，例如完整 JSON 外的合法代码围栏及已声明内容块的文本抽取；不补齐被截断的 JSON、不删除非法来源让结果强行通过、不自动增加修复模型调用。
6. 保留 candidate → completion CAS → publication 的发布顺序，取消和迟到结果不可发布；用户主动重试建立新尝试，继续引用同一不可变来源。保存仍由用户明确发起。

**验收：**用替身响应覆盖正常文章、公式转义、截断、未知字段、非法来源、取消/完成竞态、重启补发布；每种失败有可区别且不泄密的状态。再在独立授权的真实调用中复验该冻结来源，完成草稿编辑、自动保存、正式保存及 F02 的重开/版本/定位。不得恢复旧失败任务时自动付费重跑。

## 5. F03：题号“16.”被错误当成解题必要事实

### 已确认根因

题目 `f51865b2` 来自“第1章 绪论”，来源定位至物理页36和 chunk `7e4ad65d2283f48567ab`。题干要求二阶测量系统的方程、参数、响应及阻尼情形；保存的答案和解析为空。两个 `exercise_answer` 任务在检索阶段失败，均为教材证据不足。

`backend/api/exercises.py::generate_exercise_answer` 直接用含题号的 `question_text` 检索；`_supports_query_literals` 把所有两位及以上整数作为必需字面条件。因此“16.”被要求在每条支持片段出现。

| 同书同章、同一离线检索配置 | 支持度 | 最终 EvidencePack |
| --- | --- | --- |
| 保留题号“16.” | insufficient，required_literal_missing_or_no_candidates | 0 条 |
| 仅移除题首“16.” | supported | 4 条：动态标定、动态特性及数学模型 |

另一个缺口：修正题号后，support focus 只识别“灵敏度”，没有把微分方程、固有频率、阻尼比及三类响应分别纳入覆盖要求。**四条证据通过当前 gate 不等于已经能完整解题。**

### 解决方案

1. 增加通用习题查询投影，明确区分题号、来源页码、公式编号、型号及参与运算的数值。优先使用已有学习单元的题号元数据；只识别明确题首编号，题干原文、来源和数据库记录保持不变。不能删除题中所有数字，含歧义的数字保留。
2. 用来源单元/chunk/version 做同范围只读定位与邻接补全，再按题干内容检索方法证据；恢复解题所需附图、附表和跨页条件。来源仍须绑定原版本；存在 source chunk 不意味着该 chunk 自带正确答案。
3. 拆分本题 required outputs：微分方程、K/固有频率/阻尼比、题目所要求的状态表达式、过阻尼/临界阻尼/无阻尼响应、设计选型依据。题干用词如“状态表达式”存在 OCR/原意疑问时，先在原 IR 核对并允许人工校正，不擅自替用户改题。
4. 将 Router 中的检索、生成与草稿封装移入应用服务，复用现有主聊天的输入门槛、角色工厂、EvidencePack、答案后置验证和受限数学工具。保留题目来源及模式授权，不新建另一套自主回答链路。实施先核对现有服务接口，优先做无需迁移的接线。
5. 教材模式缺少部分方法时，明确列出可支持与缺失部分；用户显式选择学科通用模式后才使用模型知识，并说明来源边界。缺决定性输入时仍须补充，通用模式不免除数值/公式校验。
6. 返回的是可审阅答案草稿，不直接写习题正式答案；明确保存后才持久化。失败不阻断手动填写答案、正常作答及转错题；不能为了试解自动写掌握度或复习质量。

**验收：**题号16/17/100 不再让同一题的有效证据消失；题中的16 V、100 Ω、型号、年份和公式索引仍按其角色校验。真实第16题逐项覆盖 required outputs；缺表/缺图时停止精确解答；公式/响应有适用条件及确定性校验，最终状态不能只有“草稿非空”。
