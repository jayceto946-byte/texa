# Texa 桌面 UI 重构方案与 Sol 实施交接

日期：2026-10-03。规划：Astra。本文只规划；没有修改产品代码或用户数据。

状态：已结合五张原始截图、主代理 Electron 审查和源码核对定稿。配套审查记录：`docs/desktop-ui-audit-astra-handoff-2026-10-03.md`。

## 审阅摘要

**阶段一现在交 Sol 实施**：沿用批准过的学习/教材设计，将笔记全链路统一成“紧凑应用头 + 连贯文章 + 按需查看来源”；预检默认按实际内容，高级侧重折叠；历史行改三点入口，错题动作退出常驻正文并可靠区分草稿/已记录；统一选择与键盘行为；修复复习、练习、错题和 Goal 已发现的重复说明及行动层级。使用现有存储的错题来源查询/幂等复用属于这一阶段，不迁移数据库。

**阶段二提交具体方案再批准**：真正持久化会话置顶、归档、删除。目前没有这组后端合同，不能用 localStorage 假做完成。具体设计见第 6 节；阶段一完成不等于这三个功能已解决。永久清理、Goal 持续对话和小模型自动分类也不纳入本轮实施。

**交付标准**：16px/740px 阅读画布、48px 统一 chrome、长标题进入正文；正文无逐块来源 footer，但风险与来源仍能定位；Ctrl/Cmd+A 不选应用壳且保留输入/正文复制；有数据、空、失败、待核实、窄窗状态均验。使用隔离 Electron/fixture，不重启或操纵用户正在使用的实例、不触发真实模型付费。保留工作区现有未提交改动。

Sol 可从第 9 节顺序实施，按第 12 节逐项关闭审查问题；第 10 节记录实际验收。后文是可执行细则，不需要重新开展全应用设计系统研究。

## 1. 重构判断与交付范围

问题的共同原因是：新工作流各自定义页面头、文字等级、操作位置和状态说明，导致学习内容与管理控件竞争，来源信息又被重复铺进正文。此次应把笔记完整链路接入已有桌面设计底盘，同时收敛会话操作、错题入口和页面 chrome；不应再做一轮局部字号补丁。

保留两个内容原型：

- **阅读画布**：聊天回答、正式笔记、草稿阅读预览、目标产出。文章宽度、正文/公式排版、来源查看方式一致。
- **管理工作区**：笔记列表、错题、习题、教材、复习、目标列表、设置。紧凑页头、筛选、列表与下一步动作一致。

笔记是独立学习资产；会话是来源；Goal 是有界后台学习任务。三者可导航关联，不合并持久化身份。当前无需迁移的修复先完整实现；新会话管理持久化合同独立列出，不能用前端隐藏数据冒充归档/删除。

## 2. 证据与置信边界

### 2.1 用户直接反馈

1. 整理侧重应可选，默认按实际内容，减少开始整理前的决策；小模型自动判别作为未来方向。
2. 预检弹窗、生成、草稿、正式正文的字体布局需要整体重构。
3. 历史行的笔记图标改为三点菜单，承载置顶、归档、删除、整理为笔记，减少同屏重复入口。
4. 每个问题下常驻“记录为错题”不合理，需要覆盖已记录状态。
5. 笔记应像文章，逐块“来源 N / 待核实”不能另起一行打断；底层追溯与警告保存门槛保留。
6. header 高度、字体和控件应统一；应用壳不应被 Ctrl/Cmd+A 选中，学习内容和输入仍可正常复制编辑。
7. 长运行对话与 Goal 的入口表达需要清晰，但不能伪造 chat/turn 或引入自主循环。

## 3. 宏观信息架构与入口

### 3.1 应用壳

保留当前主导航与路由，不为本轮新增产品一级页面。壳只承载：导航、当前页面名、范围/位置、少量当前任务动作。完整笔记标题、摘要、目标说明都进入正文区域，长标题不能撑高 chrome。

每页只有一个主要内容滚动区；导航和 inspector 可各自滚动。页头固定 48px；筛选与状态条属于页头下的内容工具区，不能靠页头多行撑高解决窄窗拥挤。菜单/弹窗通过现有 portal 层，不能被行或滚动容器裁剪。

### 3.2 会话到笔记

唯一主要路径：**历史行三点菜单 → 整理为笔记 → 预检 → 后台整理 → 草稿阅读/修改 → 明确保存 → 正式笔记**。

展开历史侧栏时移除聊天顶部重复的“整理为笔记”文字按钮。侧栏收起时可在当前会话三点菜单提供相同动作，复用同一命令和同一个预检 controller；不能出现两个同义主按钮。菜单操作当前行时不应先切换会话。

Notes 列表只负责寻找已保存笔记与未完成草稿；从会话整理仍是主要创建入口。已保存/草稿/归档标签保留。无筛选的空库给一个回到学习动作；有筛选无结果给“清除筛选”；归档无记录不重复引导生成。

### 3.3 Goal 与长运行学习

当前目标页保持独立 origin：列表 → 目标约定与状态 → 当前运行/产出 → 执行详情。当前会话里有真实绑定任务时，任务状态/输入门槛/继续按钮仍在原 turn 展示。

本轮可统一 Goal 页 chrome、文档产出、状态和按钮主次；不添加伪造聊天记录，不把独立 Goal 塞入会话历史，不让打开页面自动执行。`paused` 的主操作表达为“启用目标”，`active` 的主操作为“开始执行/继续执行”，必须与后端现有两阶段状态相符。

若后续要“像对话一样持续补充独立 Goal”，须另定 goal-scoped 输入/反馈合同、预算、停止栅栏与来源，不可复用 chat DTO 假造 turn。本轮不实现。

## 4. 共享视觉角色与组件边界

| 角色 | 基线 | 使用规则 |
|---|---|---|
| 页面 chrome | 48px，19px/600 页名，28px 常规控件 | Notes、Goal、复习等接入现有 token；原生窗口按钮避让单独处理 |
| 文档标题 | 24px/600，可换行 | 笔记题目/长目标题目置于内容中；不把它当页名 |
| 文档正文 | 16px，约 1.9 行高，740px 最大阅读宽 | 与批准学习画布一致；公式/表格局部横向滚动 |
| 章节/小标题 | 18px / 16px | Markdown 层级与 Note heading 一致，不按块新造等级 |
| 控件/字段 | 13px，标签与内容清楚分离 | 使用现有按钮、字段、选择器角色；控件继承 UI 字体 |
| 支持信息/元数据 | 12px / 11px | 时间、版本、计数、诊断；不作为大段说明正文 |
| 内容间距 | 同一文章纵向节奏 | 段落、列表、公式各有间距，不能所有 block 都加相同外框和 footer |

字体沿用主题与现有阅读字体偏好。UI 不继承文楷/Markdown 字体；文档正文不混用表单默认字体。颜色使用 theme role，不为笔记再建独立配色。

优先复用 `Dialog`、`ContextInspector`、`AsyncState`、按钮和字段 CSS。可抽取小而稳定的 `WorkspaceHeader` / `ReadingDocument` / `OverflowMenu`，但先查是否已有等价能力。它们只负责布局、键盘和语义，不吸收 Notes/Goal 状态机。页面只装配；笔记范围选择、生成状态、会话管理、错题关联放 feature hook/service。

通用 menu 至少支持 Enter/Space 打开、方向键/Home/End、Escape 关闭回焦、Tab 合理离开、外部点击关闭、明确 `aria-expanded`/菜单标签。三点按钮不能放在另一个 button 内。隐藏的 persistent route 不得继续响应全局快捷键。

共享 `Dialog.tsx` 当前 focusable selector 漏掉原生 `summary`。复用预检时一并补齐并验证折叠区的 Tab 圈定；不能以换成共享 Dialog 就认定键盘已通过。

## 5. 笔记完整链路的具体行为

### 5.1 预检：默认即可开始

使用共享 `Dialog`，标题“整理为笔记”。主体首屏只呈现：会话标题/范围摘要、必要警告、一个“生成草稿”主按钮、取消。说明一句：“根据会话内容整理，生成后可修改并保存。”

“整理设置”折叠区包含：

- 整理侧重，默认 `auto`，文案“按实际内容”；其余概念、推导、解题、比较、复习保留。每次对新会话打开默认 auto，不偷偷沿用上一次手动侧重。
- 整理范围默认全部完整学习轮次；长会话时可选择完整 turn。选区、模型预算、fingerprint 仍由现有服务校验。
- 有正在生成的回答时清楚提示“本次只包含已完成内容”，采用现有 completed-only 支持；不得静默包含半条回答。

批次数、捕获精确时刻、内部 ID 收入“来源与处理详情”；首屏最多显示“共 N 轮”。已有草稿以可识别标题/来源/时间展示，突出“继续已有草稿”；不能只用短 ID 让用户判断哪个应打开。已有正式笔记作为次级链接，不冒充新生成内容。

保留校验 pending/error/empty 状态。请求参数变化时旧预检失效，不能点旧 fingerprint；关闭后迟到响应不重开。生成提交后按钮防重复、同 operation id 重试，成功进入草稿。不要因 UI 重构额外请求一次模型分类。

范围分页专项：`undefined` 表示全量，不等于已加载的 turns 数组。取消勾选一条不能悄悄把未加载的更早轮次全部排除；实现应显式切到可见的“自选范围”并说明选择数，或在现有请求合同允许下完整解析选择。不可把前端近期窗口当全部来源。

### 5.2 生成：任务进度而非空文章

页头“整理笔记”，正文统一状态区：来源会话、当前阶段、一句后台说明和下一步动作。只展示真实阶段/进度，不发明百分比。当前已有草稿/来源可以查看；正式正文只在发布检查通过后出现。

运行中以“返回会话”为常用动作，取消为次级。取消请求后显示“正在停止”直至后端确认；失败/中断提供从同一冻结来源重试、手动整理；丢弃放次级菜单并遵循原有确认语义。重启不得自动付费重跑。

### 5.3 草稿：先读文章，再编辑

页头固定：返回笔记、草稿状态、阅读/编辑切换、保存。长笔记标题位于文章顶部。自动保存状态靠近保存控件，一处表达“草稿已保存”，避免与“保存笔记”语义混淆。

生成草稿默认阅读预览。正文结构为：标题 → 可选摘要 → 紧凑的来源/待核实摘要 → 文章。详细属性（学科、标签、分类章节）放“笔记信息”折叠区或 inspector；不在阅读状态占据第一屏。编辑仍使用现有块编辑能力，不引入富文本依赖；块操作只在编辑时显示，字段风格统一，切回阅读保留滚动/定位。

有警告时常显“有 N 项待核实 · 查看”，查看可定位受影响块。正式保存仍要求确认当前 revision + warning hash；可以将确认复选放紧凑 review 区或保存确认 Dialog，不能自动勾选、只凭关闭警告继续保存或提升验证状态。编辑后确认失效继续执行原规则。

自动保存失败、CAS 冲突、关闭失败必须保留当前文字并显示重试/复制/重新载入恢复动作。不得为了页头简洁隐藏未保存状态。按现有 autosave/retained editor 机制完成导航和 Electron 退出回归。

### 5.4 正式正文：文章与追溯同时成立

阅读组件保留 block_id 锚点和来源映射，但正常正文流移除每块单独 metadata footer。选择**块侧边小型来源按钮/标记**作为初始实现：不参与文章行高，hover/focus 可强化，键盘始终可到达；窄窗预留少量侧栏空间，不能盖住文字/公式。不把来源文本拼入 Markdown，以免破坏列表、数学或复制结果。

待核实块使用持续可见的低强度风险标记，带可读 accessible label；不能只在 hover 出现。页级警告摘要提供按块跳转。来源按钮打开现有 inspector，展示冻结消息、教材证据状态、原因。`user_added` 与编辑后对齐降级保留于 inspector/块标记；文章中不用重复一整行“用户补充”。

标题/正文正常可复制；复制整篇不应混入每块来源按钮与 UI 标签。需要来源的人从 inspector 获取原文。保留原始 block 划分以便回溯，不把所有 block 拼成新字符串后丢失身份。

版本、来源会话、捕获时间、章节定位详情和历史版本收进“笔记信息/历史版本”；历史版本只读、归档状态明确、来源不可用仍能读正文。文章开头保留一次简洁“来源于 X 会话 / 已保存”即可。查证警告不能因进入历史版本而丢失。

### 5.5 列表

使用统一页头与列表标题层级。默认工具行显示搜索和视图，其余学科/教材/章节放筛选展开区，已启用筛选有摘要和清除动作。空库不占四个空字段。

行主信息为标题、必要摘要、更新时间与来源；待核实一枚状态；归档/恢复放行菜单。标题长文本最多两行，完整标题可在阅读页查看。草稿行显示实际状态（正在整理、可审阅、中断、失败），不显示内部 job status 原词。列表/筛选部分失败继续保留可用内容与独立错误。

## 6. 会话历史菜单与持久化边界

### 6.1 可立即完成的前端部分

行结构：可点击标题/时间区域 + 三点按钮。三点对 hover、focus-within、当前行可见，触屏/窄窗始终可发现。当前行选中与菜单打开互不混淆。单个 controlled 预检弹窗服务全部行；加载错误用就地重试，缓存只能注明暂未更新，不能把失败显示成“暂无会话”。

完整目标菜单顺序：置顶/取消置顶、整理为笔记、归档/恢复、分隔线、删除。已置顶有安静图标/分组，归档入口可从历史列表视图访问。当前活跃 run 不得被归档/删除动作偷偷终止；需要后端状态约束与明确处理。

### 6.2 当前缺少的合同：单独批准后实施

现有后端没有会话 metadata / archive / delete API。用户要求这些能力已明确，但仓库要求架构/数据迁移征同意；主代理应结合完整原话判断授权，不能由本规划擅自认定迁移已获准。

提交给用户的最小方案应明确：会话目录元数据（pinned、archived、revision/更新时间）；默认/归档列表；幂等修改；删除的真实含义、活跃任务约束及来源保留策略。优先后端权威持久化，不能 localStorage 过滤当归档/删除。不要直接改旧 JSON 投影，因为消息权威来源是 SQLite event log。

删除应明确区分从历史移除/可恢复软删除与永久清理。初始推荐可恢复移除，保留已冻结笔记来源；若命名“删除”需在确认框说明可恢复性与影响。永久删除及关联清理需独立合同与批准，不能级联删除笔记、错题、Goal。

批准前可完成三点菜单、整理为笔记与错误恢复，但未实现的菜单项不要伪装为可用，也不要把任务宣称全部完成。最终交付列出待批准部分及上述具体方案。该边界不阻塞笔记和其他页面修复。

## 7. 错题入口与已记录状态

移除每条问题下的常驻文字按钮，将动作放入该消息的三点菜单/既有工具区域，hover 或 keyboard focus 可发现，窄窗保留菜单入口。无需用模型判定某句话是否题目；用户明确选择“记录为错题”即进入人工校对工作流。

状态合同：未录入 → 编辑草稿 → 已正式记录。草稿建立只显示“继续整理错题”；正式保存成功并有持久化关联才显示“已记录 · 查看错题”。查询失败显示“状态暂不可用/重试”，不能当未记录再建重复项。归档的错题仍是已关联，打开时显示归档状态。

稳定身份至少包括实际教材存储 scope + conversation_id + message_id（有 turn 可辅助），不以正文 hash 或 UI 索引作唯一身份。服务层在现有 draft/source/candidate 存储上实现查询/创建或复用，处理并发双击与重试；Router 只做协议。每个当前消息页批量查询状态，避免一条一请求。未持久化消息若没有可靠 ID，应等待稳定 ID 或明确只建无关联草稿，不能生成“伪已记录”。

已有历史 draft/错题可用现存 `source_ref` 做兼容只读解析；不用迁移旧数据，也不从标题模糊匹配。原有重复记录不自动合并/删除。新保存将稳定来源 key 挂入已有来源映射，同时维持校对、题干完整性、用户确认错因和幂等回执。需要测试两个调用同时发生不会创建两个可编辑草稿/正式记录。

当前 `GET /mistakes/drafts` 上限 100 条，不足以证明历史来源不存在。必须在服务/存储侧按完整稳定来源查找（包括正式记录和已接受 candidate），然后只返回当前消息页所需结果；不能拉最近 100 条在前端扫描后把漏掉的历史项判为未记录。无 schema 变化可查询现有 JSON 字段/来源表；若性能确需新索引/迁移，另报具体方案，不悄悄超出授权。

## 8. 选择、键盘与桌面 chrome

按角色定义 chrome 不可选择与内容可选择：导航、页头、工具栏、按钮、标签为 `user-select:none`（含 WebKit）；正文、问题、引用原文、错误诊断可复制区域为 `user-select:text`；input/textarea/contenteditable/MathLive 保留其原生编辑行为。

不能全局吞掉 Cmd/Ctrl+A。先验证 Chromium/Electron 在角色 CSS 下的行为；如原生 selectAll 仍跨区选择，只在编辑器之外且真实阅读容器激活时把 Select All 限定到该容器，空白 chrome 无操作。必须同时验证键盘和 Electron 菜单 role，不仅写一个 DOM keydown。

禁用选择不得妨碍按钮点击、拖窗、链接、屏幕阅读器或复制来源。原生窗口拖动区和 no-drag 控件继续按平台分离；mac traffic light 避让与 Windows 原生按钮区域分别验证。hidden 的旧路由不能被全选或获得焦点。

## 10. 验收矩阵

### 10.1 必须实际运行的桌面场景

在隔离的 macOS Electron 测试实例检查 1280×820、1024×768、760×820；使用临时数据/fixture，不重启、不调整或持续点击用户正在操作的实例。至少默认主题和当前用户主题，导航开/关、inspector 开/关。Windows 若无法运行，写明未实测，不得由 CSS 推断兼容通过。浏览器 fixture 可先验证布局，但必须标明其不能代替 Electron 原生 Edit 菜单、拖窗、退出行为验收。

- 长中文聊天 + 块公式 + 表格 + 引用：chrome 不进选择，正文可跨段复制，输入全选只作用于输入。
- 历史行菜单：键盘进入/退出、滚动不裁切、打开非当前行笔记不先切换会话、错误可恢复。
- 笔记预检：auto 默认；改侧重；长会话自选/分页；正在生成的 turn；空内容；预检失败与迟到响应；重复点击。
- 生成：运行、取消中、已取消、中断、失败、完成；返回会话再回来；本轮不进行付费真实模型生成，可用隔离 fixture/mock 驱动状态并明确记录。
- 草稿：阅读/编辑/公式修改/重新排序、warning 确认后再编辑使确认失效、自动保存失败、CAS 冲突恢复、返回导航、退出被未保存阻止。
- 正式笔记：多层标题、连续公式、列表、长表格、>3 处待核实标记、来源 inspector、目录跳转、历史只读版本、来源不可用、归档/恢复。
- Notes 列表：有内容、空库、搜索无结果、归档空、草稿混合状态、辅助筛选失败但主体可用。
- 错题：未录入→草稿→正式记录；中途返回；刷新/重启；双击/重试；既有关联；状态请求失败；跨教材同消息身份不串联。
- Goal：暂停/启用/开始/等待输入/确认/降级结果，既有 task 身份不变；页面切换不停止任务。
- 其他管理页面：至少一个有数据状态和一个空/错误状态；只看空页不足以验证列表和按钮布局。

### 10.2 自动检查范围

- 前端运行相关 Vitest（笔记 rendering/navigation/autosave，以及新增菜单、选择逻辑、错题来源状态的真实行为测试），lint、build。不要为每个字号写实现镜像测试。
- 后端若补错题查询/复用，使用 `venv310` Python 3.10 跑相关生命周期测试；新增并发/幂等、不同来源不混淆、旧 source_ref 兼容和草稿不是已记录的验证。
- SessionNote 的冻结来源、warning hash、CAS、异步完成 receipt 现有测试必须保留通过。共享组件改变时检查现有学习与教材页面回归。
- 需要隔离数据时使用临时 fixture，不改实际学习库、索引、凭证和模型设置。不得执行真实模型 Answer Eval 或付费数据出境调用。

### 10.3 可观察完成标准

1. 三尺寸页头高度相同且控件不裁切；长笔记标题进入正文，header 无被动多行膨胀。
2. 普通用户直接点“生成草稿”无需先选整理类型，auto 请求值可验证。
3. 正常笔记连续阅读不出现每块一个 footer；任意来源/待核实仍能键盘查看并定位。
4. 已保存状态从后端/权威回执恢复，刷新后不会回到“记录为错题”。
5. 同屏没有重复笔记主按钮；已授权实现的会话菜单能力真实持久化，未实现能力诚实报告。
6. Ctrl/Cmd+A 不选壳；输入和文章复制可用；不存在用全局 preventDefault 牺牲编辑器的实现。
7. patch_notes 记录改动、验证方式、实际平台、未验证场景与剩余授权边界；不将普通修复塞入 AGENTS。

## 11. 主要风险与禁止捷径

- 大量未提交 SessionNote/Electron 工作是本轮基底；禁止 reset/覆盖、为清爽 diff 重建功能、提交他人修改。
- CSS 有多层历史覆盖。以 computed style/最终规则为准；禁止在 notes.css 尾部再堆一套高 specificity 临时补丁。
- 来源 UI 降噪容易误删验证含义。保留 block identity、revision、warning hash、冻结来源与章节版本；显示的风险不能只藏在 hover。
- UI“已记录”若由本地 boolean 决定，会在重启/失败时错误。必须区分已建草稿与正式记录，使用稳定来源身份和后端回执。
- 归档/删除涉及权威会话与独立资产。批准前不做数据迁移，不物理删除事件、笔记源快照或关联记录。
- 将页面切换、关闭 Dialog 当作取消生成会损坏现有任务语义；继续保留 explicit cancel 与 backend confirmation。
- 全局 user-select 或快捷键处理可能影响 MathLive、KaTeX、输入与隐藏路由。按区域测试，不按截图看起来没选中判断通过。
- 小模型自动判断侧重是未来研究项；本轮 auto 利用现有有界整理器即可，不新增调用、供应商分支或自主 Agent Loop。

其他页面的详细约束：

- **复习**：先显示可继续的活动会话，其次到期队列和一个开始动作；小计可一行显示。没有到期时合并今日提示与队列空态，洞察和活动记录保持可访问但不抢第一屏。统计/洞察请求失败不得影响主队列与恢复入口，不修改 SM-2。
- **练习**：首次空库给“导入习题”主动作与手动录入次动作；已有候选或未完成练习必须保留恢复路径。“练习范围”只在真的有筛选时显示具体教材/章节摘要；无筛选写“当前题库”即可。题数/顺序在有可用题时呈现，不改练习状态机。
- **错题**：页面只一个“错题”定位标题，空态“还没有错题”配一次录入；既有待处理/诊断/复习入口按有无内容保留。不能因简化 UI 去掉校对、未确认错因、作答来源和掌握依据。
- **Goal**：当前状态和可做操作紧邻题目；已有任务时其输出优先，目标说明/完成条件可折叠为详情；等待补充或确认的 gate 必须常见。执行日志默认折叠；已暂停不能显示正在继续的假象。新建/确认目标的字段和按钮套共享角色，后端动作不变。
- **聊天验证**：从结构化 check 的 label/reason 映射可读说明；已持久化旧 notice 必须保留历史语义，不能全局字符串替换公式正文。`formula` 等内部 ID 可留在诊断详情。仅知道未通过时不能编造“计算错误”，应说检查未通过/需要核对。运行完成与内容未验证可同时出现，不用统一绿色 check 掩盖后者。
- **教材与设置**：本次尚无新的已复现缺陷，维持批准基准；共享角色变更后做回归，不能仅因它们未审查完就临时大改导航或设置布局。
