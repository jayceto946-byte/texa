# Texa userData 目录迁移方案

## 状态与边界

本文定义产品从旧名称升级到 Texa 时，Electron `userData` 目录的独立迁移与回滚协议。当前版本**只保留兼容路径，不执行迁移**：

| 运行模式 | 当前兼容目录 | 未来目标目录 |
| --- | --- | --- |
| 打包版 | `%APPDATA%\考研智能辅助系统` | `%APPDATA%\Texa` |
| 开发版 | `%APPDATA%\kaoyan-assistant-desktop` | `%APPDATA%\texa-desktop` |

在本方案完成实现、测试和至少一个正式版本的观察期之前，不得删除 `desktop/main.cjs` 中的旧路径覆盖，也不得删除、移动或就地改写旧目录。

## 迁移原则

1. **复制后切换，不原地移动。** 旧目录始终是可直接回滚的完整副本。
2. **一次只允许一个迁移进程。** 使用目标目录旁的独占锁文件，检测到另一个实例或活动后端时中止迁移。
3. **先做空间和完整性预检。** 目标卷可用空间至少为源目录大小的 1.2 倍并额外保留 512 MiB。
4. **不追随链接。** 拒绝 junction、symlink、reparse point 和越过源目录边界的路径。
5. **用户数据优先。** `data/progress`、`data/images`、`data/books`、`data/chapters`、`data/vector_db`、`.env`、`mineru_output` 和桌面设置必须复制；日志和可重建缓存可按清单排除。
6. **失败保持旧版可启动。** 任一检查失败都继续使用旧目录，并显示可诊断但不阻塞启动的状态。

## 状态机与落盘协议

迁移器使用目标目录同级的临时目录，例如 `%APPDATA%\Texa.migrating-<uuid>`，并在其中写入 `migration-state.json`：

```json
{
  "schema": 1,
  "source": "%APPDATA%\\考研智能辅助系统",
  "target": "%APPDATA%\\Texa",
  "phase": "copying",
  "started_at": "ISO-8601",
  "app_version": "x.y.z",
  "source_fingerprint": "sha256"
}
```

允许的阶段为 `preflight -> copying -> verifying -> ready -> activated`。流程如下：

1. 关闭 Texa 后端并确认不存在持有 SQLite、Chroma 或配置文件的应用实例。
2. 对源目录生成清单：相对路径、类型、大小、修改时间；关键 SQLite/JSON/环境配置额外计算 SHA-256。
3. 将文件复制到临时目录。SQLite 必须在应用退出后复制；若仍存在 `-wal`/`-shm`，先使用只读连接执行一致性检查，不擅自删除伴随文件。
4. 校验文件数量、总字节数、关键文件哈希、JSON 可解析性、SQLite `PRAGMA quick_check`，并以只读方式打开 Chroma 元数据。
5. 将临时目录原子改名为目标目录；若目标已存在且非本迁移器创建，立即中止并保留双方目录。
6. 写入目标目录 `migration-complete.json`，记录源/目标、清单摘要、应用版本和完成时间。
7. 下一次启动仅在完成标记和校验均有效时选择目标目录；否则继续选择旧目录。

## 冲突处理

- **只有旧目录存在：** 提供一次性迁移，默认先创建备份并要求用户确认开始。
- **只有目标目录存在：** 校验完成标记；有效则直接使用，无效则停止并提示修复。
- **新旧目录都存在：** 不按修改时间自动合并。若目标有有效完成标记且源指纹匹配，使用目标；否则让用户选择继续旧目录、检查目标目录或重新迁移。
- **两个目录都不存在：** 作为全新安装创建目标目录。
- **迁移中断：** 下次启动检查临时目录状态；允许从清单续传或删除仅由迁移器创建的临时目录，不触碰源目录和既有目标目录。

## 回滚

正式切换后的至少两个稳定版本内保留以下能力：

1. 启动参数或环境变量 `TEXA_USER_DATA_MODE=legacy` 强制使用旧目录。
2. 设置页显示当前数据目录、迁移时间和“切回旧目录”操作。
3. 回滚只切换路径，不把目标目录反向覆盖到源目录。
4. 若用户在新目录产生了新记录，回滚前导出增量备份；自动双向合并不属于首版迁移范围。
5. 只有用户明确确认、完成独立备份且观察期结束后，后续版本才可提供“归档旧目录”；不得静默删除。

## 实现与发布门槛

迁移逻辑应放在独立模块中，由 Electron 在创建窗口和启动后端之前调用；业务后端、数据库模型和向量索引格式保持不变。发布前至少覆盖：

- 空目录、小型目录、大型向量库、长路径、中文路径、磁盘不足和只读文件。
- SQLite WAL、Chroma 打开占用、进程并发、复制中断、校验失败和目标目录冲突。
- 从旧版直接升级、迁移完成后重启、强制 legacy 回滚、回滚后再次升级。
- 教材、错题、会话、ConceptMemory、复习队列、图片、配置和向量检索逐项 smoke test。
- 安装、自动更新和卸载；卸载继续不得删除学习数据。

满足以上门槛后，先发布一个“可迁移但仍默认旧目录”的观察版本；确认无数据丢失报告后，再发布默认使用目标目录的版本。旧路径兼容代码至少再保留两个稳定版本。
