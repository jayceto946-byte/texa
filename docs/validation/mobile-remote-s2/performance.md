# S2 第一批性能与验收对照

最终同口径：`baseline/results.json` → `final/results.json`。5冷/20热，390×844，固定400ms latency / 5Mbps下行 / 1Mbps上行，本地HTTPS/HTTP1.1；100条合成消息（50轮）。冷画布等待100条 Markdown 实际渲染，不采用懒加载占位。**这是浏览器受控网络测量，不是真实 DERP 或真实模型测量。**

| 指标 | 之前 p50 / p95 | 之后 p50 / p95 | 判定 |
|---|---:|---:|---|
| 冷进入至完整夹具可读 | 6488 / 6789ms | 6275 / 6371ms | 小幅差异，样本少；不宣布冷启动目标达成 |
| 已加载工作区切换会话至可读（20次） | 1476 / 2012ms | 885 / 901ms | p50约降低40.0%，p95约55.2%；尚未达到200ms热快照目标 |
| 响应正文结束→正文显示 | 1065 / 1598ms | 474 / 489ms | Markdown复用降低显示路径成本；包含布局/绘制和观测延迟 |
| 会话请求→正文接收完成 | 410 / 412ms | 411 / 412ms | 网络/传输基本不变，没有归因于DERP改善 |
| 夹具API应用到响应头 | 3.0 / 16.2ms | 2.1 / 4.0ms | 后端业务未改；小差异不作为API提速成果 |
| 每次冷进入目录读取 | 2次 / 1240B gzip正文 | 1次 / 620B gzip正文 | 五次均确认，省一请求；native一次失效也只有一请求 |
| Harmony下载 | 0次 / 0B | 0次 / 0B | S0/S1已有系统字体策略，本轮无新增收益 |
| 流式上翻的位置 | 120→92009px | 120→120px | 修复已确认的自动跳底 |
| 错误终态后的已收到正文 | 第20片段不可见 | 第20片段仍可见 | 同一canonical假流，错误仍明确显示 |

p95采用排序后的nearest-rank；冷样本5次，p95就是最大样本，仅观察。冷范围之前6242–6789ms，之后5949–6371ms；热范围之前1294–2012ms，之后588–901ms。原始范围、资源大小、TTFB/body阶段、Server-Timing、paint/longtask与每次采样均保留，不跨客户端/服务端时钟相减。

字节传输与请求往返未完全可独立测量：CDP latency在本机Resource Timing中可能主要落入`headers→body`，不能将400ms都算作下载字节成本。真实VPN丢包、拥塞和重路由不由该夹具模拟。新可选诊断导出可从手机补充同源资源/Server-Timing；未覆盖端到端SSE服务器产生→客户端paint、完整模型/识图时钟或真实INP。本轮不伪造这些分段数值。
