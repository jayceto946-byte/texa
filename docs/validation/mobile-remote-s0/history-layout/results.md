# Mobile Remote S0：历史读取与窄屏布局修复（2026-10-08）

用户 Redmi 实测已能进入问答页、读历史并打开会话；反馈约1秒切换等待、历史反复刷新和导航重叠。本轮没有 Android 设备控制权；下述浏览器夹具验证不能替代 Redmi 真机验收。

## 已确认的问题与改动

- `MainLayout.tsx` 把消息数、末条消息阶段/ID用于历史刷新，`LearningContextSidebar.tsx`又依赖conversationId；打开旧会话会触发列表重读并清空已有列表。改为回答运行结束后刷新，保留管理变更、范围/分类切换、显式重试；同范围刷新保留已有列表，只在范围改变时清空。加载更多在首列表更新时禁用。
- 点击当前会话原来仍请求详情。现在复用当前显示内容：手机关闭抽屉，桌面保留侧栏。没有为其他会话增加可能过期的正文缓存。
- 会话选择没有取消与迟到响应隔离。现在使用AbortSignal和选择序号，取消前一次选择；新会话也取消待返回的选择。只有被点选行显示读取状态，失败保留错误和重试入口。
- 实际393×852渲染：功能栏矩形y=0/h=514，历史栏position=fixed、x=56/y=0/h=852，二者确实重叠。窄屏改为同一抽屉正常流，功能导航两列；修复后功能栏y=0/h=260，历史栏y=260/h=592。长历史标题换行；窄屏页头允许增长/换行，输入工具允许换行。所有布局覆盖仅在≤919/760px生效。
- `backend/remote_reads.py`增加有限的会话详情GET压缩和Server-Timing，与既有列表优化一致。严格只匹配`/api/chat/conversations/<id>`；子路径、SSE和写操作不经过该压缩。日志仅固定标签、状态、耗时和字节数；no-store、鉴权保持。用于减少正文传输、进一步区分服务耗时，不能证明1秒等待的全部根因。

## 真机复测

1. Redmi刷新原Serve地址，沿用现有临时令牌；若被要求重新连接，只从原桌面受控复制，不发给开发者。
2. 展开侧栏，确认功能区与历史顺序排列，长标题可读；打开另一会话，再打开侧栏，确认列表不闪空；点当前会话应立即回到内容。
3. 记录不同会话首次打开的耗时与重复点击当前会话的耗时。首次远程读取仍包含网络往返、正文传输和渲染，不承诺毫秒级；若仍约1秒，用原后端`S0 read session-detail`的固定标签耗时/字节数继续区分服务和传输，不索取Token、HAR或含鉴权的请求日志。
4. 在已有教材范围完成一条文字问答，检查SSE正文、引用与刷新后的持久化结果。另做断网、桌面退出和未授权设备验证。

当前未验证：本轮Android改动后的耗时与布局、真实文字教材问答/SSE/引用、校园网、未授权设备ACL。用户反馈的“问答页与历史可用”不等于这些项目已签收。S0没有新增原生壳、拍照、错题或笔记功能。
