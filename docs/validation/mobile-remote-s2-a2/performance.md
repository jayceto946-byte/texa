## 同口径记录

时间均为 ms。TTFB 是浏览器 requestStart→responseStart；服务端为 Server-Timing `texa_read` 的响应头准备耗时，两者相减仍包含链路/排队/系统调度，不能精确归因单独 DERP。渲染计时从权威消息提交开始，等待 lazy Markdown 就绪与两帧，包含布局/帧等待，不等同纯 React CPU。

`encodedBytes` 为编码后响应正文；`decodedBytes` 为解码正文；兼容字段 `wireBytes` 是浏览器 transferSize，包含浏览器估算的响应头，**不是 DERP/TLS/HTTP2 物理线路字节数**。缓存资源的 encodedBytes 不能计作实际下载。服务端日志 `response_body_bytes` 同样不含 HTTP/TLS 开销。失败且没有响应头的资源在 v2.1 输出 null；旧 v2 的超时资源存在伪正文耗时，剔除其下载分析。

## 实际改动及边界

1. `BookReadCache.chapter_count` 缓存已成功验证的章节数，最多64项。依赖章节 JSON、Canonical JSONL、active manifest 的完整 SHA256、大小/mtime；包括大文件同大小同时间戳变更也会失效。校验前后签名不一致不发布缓存，失败不缓存，既有失效流程清除缓存。miss 清除依赖 JSON 快捷缓存后重新走原校验；引用章节、教材版本定位、完整章节返回没有改变。
2. opt-in `?texa_perf=1` 轻量诊断 v2.1：分辨固定请求种类/操作、导航、资源缓存与传输、有限请求头/正文、Session 渲染、文字 SSE 头/首传输片段/字节、图片 multipart 上传完成与字节、鉴权 Blob 下载及可用时刻。SSE 首传输片段不等于首模型答案，Blob 可用不等于图片完成解码。记录有界，不输出原 URL、消息、用户/会话 ID 或 token，默认关闭，不改变超时和鉴权。
3. 有限只读接口增加 Server-Timing 和服务端正文字节日志，保留既有 Range/gzip/SSE 行为。`remote-ready?performance=1` 复用鉴权读取后端 import 时源代码身份与当前静态壳身份；不通过进程环境提取凭证。
4. 修复刷新后保留当前 Session ID、内存正文为空时点击同一 Session 被短路的问题：仅已加载正文或仍在回答时跳过重读。复现为选择 Session→刷新→再次选择同 ID→正文不出现。修复后走既有权威分页读取，不引入历史缓存，不改变运行权威。
