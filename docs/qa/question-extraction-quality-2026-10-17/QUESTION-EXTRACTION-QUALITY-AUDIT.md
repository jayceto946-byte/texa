## 2. Pipeline Architecture

实际默认路径如下。Markdown存在于来源包，但本次运行直接读取已持久化 Canonical IR；没有重新解析Markdown、重新OCR或调用模型。

| 阶段 | 实际模块 / 函数 | 输入→输出、规则及损失点 |
|---|---|---|
| 既有OCR结果 | MinerU 4.0.8结果ZIP；`MinerUAdapter.from_output_dir` | 原PDF本轮不可用。结果包保留 structured_content、Markdown、裁图；原OCR怎样识别符号不能从本轮运行还原 |
| 历史适配/发布 | `ingestion/mineru_structured.py`；Canonical持久层 | 本数据由 `mineru-structured-content-v1` 生成。块保留text、type、页码、bbox、equations、原图资产与source_page_idx/source_block_index；标题/空白/表格表示可被规范化。当前源码适配器已为v3，本轮没有重适配旧IR |
| 正式入口 | `backend/api/exercises.py::analyze_textbook_exercises` | 请求book/chapter/page/source_mode/limit；先调用教材抽取，有单位则按单位分析，否则走旧文本切分。`use_llm=false` |
| 来源与范围 | `extract_textbook_exercise_text`、`load_workflow_book` | 加载同书IR；可检查本地active manifest；按章节/页/heading筛选。本副本没有真实向量索引，不评价检索。IR存在时提前返回，未执行source-package、中间chunks、PDF/Kimi等fallback |
| 学习单元识别 | `document_workflows.py::learning_units` | 例题前缀或“习题”等路径中的题号开启单位；同scope追加块；heading、path变化或部分paragraph_title结束；80块/8页安全边界。数字括号标题被视作子问，可能吞入下一小节；图按阅读顺序落到最近活跃单元 |
| 展平 | `LearningUnit.text`（行99–101） | 对非空block.text做双换行join。保留277块的可读文字，但图像像素/资产身份、公式块类型和角色不进入字符串；空图块消失，图题可能仍在 |
| 候选适配 | `textbook_exercise_importer.py::analyze_learning_unit_candidates`（688–700） | 每个完整unit.text送`analyze_candidates(...limit=1)`。来源字符串含书/章/物理页区间/unit_id。**这里没有独立题干/解答分离阶段**；也不重新按题号切分学习单元 |
| 元数据/校验 | `exercise_importer.py::analyze_candidate` | question_text基本仅strip；题型按全字符串关键词/选项regex，知识点用固定通用数学/运筹关键词，difficulty/confidence为启发式。answer/explanation沿dataclass默认空。无“题干混解”“缺图”“解答归属”校验。本次没触发截断/多题/短题告警 |
| 可选结构化支路 | `refine_low_confidence_candidates`；`attach_answers_by_number` | 前者仅显式模型修复时可填答案/解析，本轮禁止且未调用。后者仅独立答案文件编号匹配，非本次教材路径。不能据此说默认教材抽取已有答案分离 |
| 重复标注 | `_candidate_outputs`；`question_fingerprint` | 只与同书已有库比对。指纹是全题干lower＋删除所有空白后的SHA256；不是语义相似度。候选之间的重复到入库add_batch才再去重 |
| 候选校对 | `candidateOperations.ts`、`useExerciseImportCandidates`、`CandidateReviewWorkspace` | issues是validation_issues非空数；duplicates是duplicate_of非空数。人工可编辑、拆/并；默认全选，无逐题核实回执。“全选”不是已校对；按空行手动拆分会清空原答案/解析并需重新核对 |
| 入库/练习 | `ExercisesPage::importSelected`；`batch_add_exercises`；`ExerciseBank.add_batch` | UI统一确认后提交完整题干/答案；API不接收候选质量证据，仅过滤空题干，重复默认跳过。needs_review是状态，不是禁止进入练习的栅栏。来源字符串/随机origin_id保留，但不是版本化完整block/asset绑定 |

`DocumentBlock` 足以回查基本来源；候选 DTO 没有typed `source_block_ids`、题干/解答块角色、required assets或内容完整性判定。API的`extract.units`仍有来源块ID，但每个候选和正式Exercise没有保留相同结构合同。不能把“原文还在”当作“可安全独立练习”。

## 6. D-01 Root Cause

| 追溯节点 | 实际证据 | 结论 |
|---|---|---|
| MinerU原结果 | 物理p14，即page_idx=13，block_index=12/13/14；分别为题干、`解:`开头段、后续解说 | CONFIRMED：已分成三个块，不是OCR先把题干解答塞进同一个块 |

| LearningUnit | 例题前缀开单元，三个块被保留进一个完整学习材料单元，直到下一标题 | CONFIRMED：对RAG/例题阅读这是合理保真行为，不能全局改成只留题干 |
| 候选投影 | `unit.text` join后直接交`analyze_candidate`，其question_text=text，answer/explanation默认空 | **CONFIRMED：主要根因是教材候选把“完整材料”当“题干”，缺少分离合同** |
| 校验 | 仅空知识点提示；没有混解检测 | CONFIRMED：没有发现真正内容缺陷；并非发现后有一个确定性阻断被绕过 |
| 校对/入库 | 用户统一确认；DTO不携带结构校对证据；非空题干可保存needs_review并进入练习 | CONFIRMED：不确定候选与可靠练习内容之间缺少结构门槛。合成隔离探针A01复现，不写真实库 |

本样本14/14已给解例题都出现同类缺口；这证明**本配置下对带解例题是系统性的投影问题**，不等于108/108错误，更不等于其他教材的错误率。

其他根因独立存在：

- **CONFIRMED**：C091/092/093/096中的数字括号小节被`_SUBQUESTION_START`豁免为子问，已有IR又把这些原生paragraph_title保留为paragraph；讲解扩入例题。标题元数据与单位边界共同造成，不宜用“解之后全部是答案”兜底。
- **CONFIRMED**：图3.60在源页稍后，物理上仍有原图，却被最近活跃单元C033吸收，真正引用者C031缺图；展平/DTO进一步丢失可读图身份。OCR阅读顺序是否本来错误为UNDETERMINED，因为没有整页原PDF。
- **CONFIRMED**：42个公式块的源文字仍在，但类型/显示界定不随字符串传播。现有前端能补救不少裸LaTeX，不能一概宣称公式全丢；同一预处理＋remark-math/KaTeX探针仍在C091/C096发现9次“tag只能用于display”错误，C091/C093/C094还存在6个公式块未被识别成对应math节点，合并涉及4个候选。详见[表示探针](./math-probe-summary.json)，它不是数学真值或新的Electron验收。
- **CONFIRMED / LIKELY**：C091局部裁图与原OCR的符号/括号差异证实源转写层已有问题；具体是OCR模型还是其后处理为LIKELY/UNDETERMINED。C094裁图证实孤立等式片段存在、同一基线多块分离；恢复原式关系需要核对，不能断言它们全是图中标注。
- **UNDETERMINED**：完整原PDF语义、各答案数值正确性、全书真实漏题数。本轮没有用模型补出缺失原文。
