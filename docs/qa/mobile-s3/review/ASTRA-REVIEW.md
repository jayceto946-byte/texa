# Texa S3 移动端产品设计独立审查

审查日期：2026-10-14。审查人：本次指定 Astra 审查 agent。结论：**支持小范围修正后继续移动端验收，不支持现在新增底部导航、重做全站信息架构或全面卡片化。** 当前最好的基础是学习回答、笔记正文和错题重做的阅读结构。主要问题是手机上仍把桌面管理操作直接排进学习路径，以及有限宽度下操作栏没有稳定的优先级。

本次仅审查并提出建议，没有修改生产代码，没有运行模型服务、修改网络或接管实施。以下建议均不是已实现行为。

## 应当保留

- **对话采用文章流是正确方向。** 01、05、08 的小节标题、推导和正文形成连续阅读，不需要改成逐条气泡或增加大面积卡片。桌面学习页的内容轴尤其清楚，手机应延续这个身份。
- **笔记阅读有清楚的文章层次。** 03 的标题、摘要、小节和折叠信息合理；历史版本留在低频位置。不要为了移动端加入逐段来源卡片、核实徽标或额外保存告警。
- **错题展示了用户自己的作答。** 04 的“我当时怎么做”和“应怎样修正”比只展示标准答案更符合复习目标；重做先作答再看反馈的单列顺序值得保留。
- **设置已形成可理解的逐层进入方式。** 06 的单列目录、详情与返回设置可以继续使用。两个模型模式选项并排本身不构成问题，它们是一个短选择组，不是旧的双栏设置页。
- **错误、加载、空状态已视觉区分。** 07 的重试、骨架和引导有不同用途；错误截图没有伪装成“还没有笔记”。应在现有基础上检查局部失败文案与主体结果是否一致。

## 对初步判断的独立修正

**抽屉拥有七个业务入口，不足以单独判 P1。** 01 中业务入口位于上部，历史位于下部，选中态也可见，整体并非完全不可扫描。问题更接近 P2：设置与学习入口混排、图标语义偏密，以及页面返回依赖通用抽屉。先增加上下文返回、把设置稳定放到抽屉底部，再观察真实跨域切换成本。不要同时重排全部入口和历史管理。

**教材管理功能并非错误功能。** 技能的产品模型明确把 Library 定义为材料管理与导入。移动端的问题是管理动作压过了学习动作，不能以此删除主辅角色或重新准备能力，也不必把整个教材页改造成一个大“继续学习”首页。优先对可用教材增加学习入口、降低维护动作权重，并保留批量管理的桌面优势。

**章节重点的双框属于 P2。** 02 右图上方大目录框和下方文章框让短内容看起来像两份附件，章节标题反而被夹在中间。可把顺序改为章节标题、教材来源、折叠目录、正文；只有确有定位价值时默认展开目录。正文使用现有阅读画布，不需要专门设计新卡片体系。

**原始元信息属于 P2，先确认数据来源。** 02 可见 `qa-book` 与 ISO/UTC 时间；若生产确实把内部 ID 和原始时间直接呈现，应换成教材名、适合用户时区的日期并将生成时间降为次级信息。测试注入字符串本身不是生产缺陷证据，也不能用日期截图推断复习调度错误。

## 最小信息架构建议

保留现有抽屉和业务域，不新增平行的手机产品入口。先补足两条位置连续性：

1. 教材列表 → 章节/重点 → 就本章提问 → 当前答案及来源 → 返回同一章节和阅读位置。
2. 来源会话 → 整理笔记 → 阅读/编辑 → 明确保存 → 笔记阅读 → 返回来源会话。

“返回”需表达真实目标，例如“返回泰勒公式”或“返回来源会话”，不只放一个含义不明的侧栏图标。直接打开深链接时则提供稳定的上一级，不伪造不存在的浏览历史。错题详情与重做已具备“返回档案/返回复习”的局部模式，可以复用，而不必在全局再发明一套导航。

**当前不建议底部导航。** 现有学习页底部已经承担输入、发送和停止，新增常驻导航会进一步减少正文及键盘上方空间。图片没有提供频繁跨域切换受阻的证据。待真实手机走完整学习闭环后，若仍反复打开抽屉才能在少数核心域切换，再单独评估；不把底部导航作为“像手机应用”的装饰要求。

## 具体视觉规则与页面方向

- 移动正文左右留白以 16–20px 为基准，沿同一内容轴对齐标题、题干、公式、来源和正文。回答和笔记正文优先 16px、行高约 1.6–1.75；次级元信息约 12–13px。先核对 CSS 和设备呈现，再调整，不能由合成图缩放直接断言字号。
- 顶栏通常固定一个明确的主动作，标题可在正文按内容自然换行，但操作不能把顶栏挤成随机两层。确需第二行时必须是设计好的状态/范围行。
- 蓝色实心按钮用于当前一步的主要动作；返回、预览、管理用轻量按钮或文本。触控区域最少 44px，邻近独立操作建议保留至少 8px 间距。
- **学习页：** 保留自然文档流、范围入口和来源检查；过程默认摘要、按需展开。05 的重复正文是合成测试内容，不列为生成质量缺陷。阶段名、工具名、停止和恢复是否准确必须用真实交互验证。
- **教材页：** 手机分类默认简洁显示当前路径，可展开选择；将维护内容从每本书的常驻行中收起。桌面表格仍适合管理，不需同步改造成手机式卡片。
- **章节重点：** 标题和教材身份先于目录；阅读区减少重复边框；打印保持低频位置，手机不必把它作为唯一显著顶栏动作。
- **笔记页：** 保留目前阅读层级；编辑时降低重复题头的高度，块操作按 44px 命中区或操作菜单解决。不要新增所有块常驻的大按钮排。
- **错题页：** 详情顶部短题干与下方完整题目重复，可让顶部以章节/题型或简短摘要承担定位；避免在手机上读两遍同一句题目。保留“我当时怎么做”，将现在重做和提交做成可准确触控的主动作；参考答案继续折叠。
- **设置页：** 保留单列导航与逐层返回，检查长模型名及键盘出现后的滚动。截图里“新方案 未保存”与“选择即应用”同屏，应实测并说明正在编辑与已经应用的对象，避免用户误认保存结果；静态图不足以判定配置状态错误。
- **状态页：** 局部辅助模块失败时说明失效范围；主体笔记失败则明确“笔记暂时无法读取”。加载时保留稳定页面身份。空状态里的“去会话整理笔记”说明可以保留，不需增加教程式首页。

## 复测与暂不投入

实施前先用实际 DOM 和交互确认触控区、公式溢出、路径入口；实施后优先覆盖 360/390/430px 的闭环与软键盘、前后台切换、断网重连及一次明确中断恢复。然后回归 Electron 的 1280×820、1024×768、760×820，确认共享样式没有伤害桌面阅读和管理表格。

前后台恢复与首次确认丢失属于独立可靠性验收项。这里没有 SQL、重复提交、实际工具调用或会话对账证据，不从静态图推断数据事故，也不把视觉清楚当成恢复正确。验证记录必须分别列出静态图片检查、浏览器交互、原生 Electron 和真实手机的完成范围。

暂不投入：底部导航、全新移动首页、全站卡片重绘、桌面整体换肤、复杂手势导航、新阅读器、模型路由重构、同步数据库或 Agent Loop。它们不能替代当前几个明确的操作与连续性问题。

**建议交付顺序：先确认闭环入口与返回合同，再修输入区及笔记编辑操作栏，然后集中校准触控区和公式可访问性。** P2 的目录、元信息和局部间距可随相关页面顺带调整，不宜另开大规模视觉重构。
