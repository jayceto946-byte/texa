## 2. 共用视觉和交互约束

- 继续使用 ApprovedWorkspace 的标题、正文、控件、元信息角色。内容标题24px、分组标题18px、表单/控件沿现有角色；不通过把正文和诊断字缩到10px换取“轻量”。
- 问答、笔记阅读、单题作答使用约740–800px的主内容轴；管理列表可更宽。问题、答案、来源、作答输入对齐；760窗口变单列并让导航退让。管理页不要套第二层宽大卡片来包住整个页面。
- 一个局部阶段只有一个主要推进动作。状态文字只保留影响理解或决策的信息；错误、待输入、待确认和未核验仍需可见文字，不能仅有颜色。
- 动作和结果用真实名字：“查看”不等于提交，“草稿已保存”不等于正式笔记已发布，“本次任务完成”不等于目标完成，“运行耗时”不等于学习时长。
- 所有延迟、失败和并发恢复复用现有权威状态；保留已呈现内容与用户输入。键盘焦点、滚动位置和用户主动展开选择不能因普通后台刷新被重置。

## A. 概念问答与过程展示

### A1. 解释策略：按问题选择有效解释，不规定段落模板

当前 refined prompt 已包含“不套固定教学流程”和证据边界，但“抽象内容可用一个简短例子”力度不足，容易产出正确但接近教材复述的回答。本轮应明确“解释用户卡住的关系”，同时保留用户只要定义/结论时的简短回答。

建议给 refined 与 general 两条策略同步加入以下语义（工程可改写措辞；版本号随内容更新）：

> 根据当前问题和用户明确表达的理解程度组织回答。概念或原理问题先回答它在描述什么、为什么有用，或用户卡住的那一处关系；用熟悉语言把直觉与准确表述连接起来，不能只换词复述定义。只有确实能降低理解成本时才加入一个具体例子、反例、图景或类比，并点明它对应哪个条件、在哪一点不适用。用户要简答时保持简短；用户要推导、计算或例题时展开必要步骤。追问优先补上新的解释角度，不重复上一轮整套讲解。不要为每题强行安排定义、直觉、例题、总结等固定栏目。

| 问题/已知理解 | 回答重点 | 避免 |
|---|---|---|
| “什么是/怎么理解” | 一句直接解释，连接准确条件；必要时一个最小具体例子 | 连续堆性质、定义的同义复述 |
| “为什么/有什么用” | 给出机制、解决的问题或容易失败的一步 | 把结论本身当原因 |
| “区别/关系” | 同一比较维度与边界；一个能区分的反例通常胜过两套百科 | 只并列定义、遗漏用户比较对象 |
| “我还是不懂/直观一点” | 降低符号门槛，换表示或例子，只补卡点 | 默认认定用户基础差、重复长答案 |
| “证明/推导” | 前提、关键变形及成立理由；必要计算完整 | 用类比替代证明 |
| “做这道题” | 问题目标、方法选择依据、必要演算与结果 | 一律先讲整章概念、强制互动闯关 |
| “只要公式/简短回答” | 直接所求及不可省的条件 | 附带无关例子和课堂式总结 |

证据边界不放松：教材事实仍只取本轮EvidencePack；准确解释可以重组证据中的关系，不能新增未经支持的教材结论。自行构造例子沿用补充例题标识，使用已有证据支持的概念/公式，不冒充教材原题；类比说明适用边界。纯通用模式允许模型知识解释并遵循其既有合同。用户理解程度只来自当前表达和允许的相关上下文，不以问答次数推定掌握，也不自动写ConceptMemory。证据不足和关键输入缺失仍遵循Runtime。

例：等价替换相减问题可先讲“相减可能恰好消掉主要部分，被忽略的小误差就成为剩下的全部”，再用有支持的sin x展开连接公式。不要由此写成“加减绝对不能用等价替换”；应说明需要比较误差与目标表达式阶数。

### A2. ExecutionTrace：一条稳定摘要，按需展开真实记录

必须保留真实事件、顺序、结果、来源预览与失败诊断；不展示或伪造模型内部思维。默认态为固定内容轴的一行：状态图标 + 当前操作短句 + 耗时 + 展开箭头。可有一行有用副说明，最多两行；取消默认最近两个已完成步骤列表，避免检索/生成切换时上下跳动。

- 当前操作名称从真实活动映射，如“查找教材内容”“计算并校验”“正在回答”；没有事件时只说“正在处理”，不编造任务清单或完成进度。
- 收起摘要在整个turn中持续占位，同一DOM区域内更新，常规文字切换可用120–180ms的opacity过渡；不用轮播、打字动画、闪烁省略号或模拟百分比。快速事件可不逐一呈现在收起态，但展开历史不能丢。
- 开始流式正文后保留摘要的位置，正文单独累积；终态保持同一行变为“处理完成 · 用时…”或真实异常，不移到答案下方，不用终态强制收起用户已展开的详情。现有 `useEffect([terminal])` 重置展开状态应去除或限制为新turn初始化。
- 正常完成默认无额外详情；失败/缺输入/待确认/降级保留可见的短原因，并由既有LearningTaskActions提供恢复操作。过程条不复制第二组确认/恢复按钮。
- 详情第一层为按实际插入顺序的步骤摘要，每步只用一个状态标记；工具输入/回执、证据预览和错误详情按需展开，避免现在双图标+小字堆叠。摘要/必要诊断采用12–13px，正文证据阅读可13–14px；来源定位保持可打开。
- “检索到的段落”和“交给回答生成的证据”继续区分；不得将检索数量当作最终有效引用数。缺失、skipped、unknown明确显示，完成图标不覆盖degraded/unverified。
- 耗时只表示本次处理。运行时更新不进入每秒aria-live播报；只播报有意义阶段和终态。减少动态效果偏好关闭过渡与旋转。

验收：真实或受控确定性事件覆盖检索→工具→生成→完成，至少一次失败/待补充/停止恢复；展开过程中结束不丢焦点、不折叠、不覆盖已输出正文。当前聊天静图不足以通过此项。

## B. Goal：先表达要完成什么，再表达系统在做什么

### B1. 对象关系和不做的功能

| 对象 | 用户理解 | 页面表达 |
|---|---|---|
| Goal | 持续的学习目标与完成条件 | 目标标题、范围、完成条件、启用/暂停/完成状态 |
| LearningTask | 为目标或一次问答执行的有界工作 | 本次任务、输入门槛、运行状态、结果、恢复动作 |
| Session | 一组学习对话的来源和阅读上下文 | 仅存在真实来源时显示“来源会话”；独立目标不能伪造会话 |
| schedule | 何时触发下一次允许的执行 | 次要安排区，具体时间/重复规则；不是另一个目标，也不是学习计时器 |

评估结论：本轮**不新增全局计时器、悬浮任务球或第二个全局任务中心**。用户高频需求是问答、读笔记、作答，运行时间可在过程条局部看到；离开Goal后任务仍继续的发现需求，现有导航入口和返回详情足以支持基础路径。全局聚合需要跨任务权威、活动计数、异常去重和关闭/恢复语义，目前缺少使用频率证据，收益不足以抵消复杂度。保留现有“目标与任务”导航；跨页通知/导航小徽标可作为后续建议，需确证长任务切页频率、已有全局数据源和需要用户处理的状态，再单独设计。复习页重复“目标与任务”按钮可去掉，侧栏已有入口。

### B2. 目标详情顺序

1. 标题及一行范围/目标状态。标题24px，不将“已启用”写成“正在运行”。
2. 目标说明简短展开，完成条件默认可见（多于3条可折叠剩余项）。空条件说明“尚未设置完成条件”，不能以空合同暗示可自动确认掌握。
3. “本次任务”区域承载状态、唯一主动作及结果。未执行时用“还未执行”及“开始执行”，无需“执行与定时安排”大标题在前、“尚无当前任务…”长说明在后。
4. 任务结果保持阅读画布；待输入/确认先于结果显示。执行记录折叠。结果未核验应显示实际限制，不用“已完成”抹平。
5. 次要目标管理：暂停/启用、定时安排与目标完成。定时编辑按需展开，保存后只留“下次执行… · 每…”与“修改”；没有安排时留“安排定时执行”。

### B3. 控件状态表

| 真实状态 | 主动作 | 其他可见信息/动作 |
|---|---|---|
| draft/paused且无运行 | 启用目标（其语义仅启用） | 未自动开始；启用完成后才出现开始执行，不暗中合并 |
| active且无任务 | 开始执行 | 暂停目标次要，定时安排更次要 |
| running | 当前任务运行状态 | 停止当前任务由既有task动作负责；若保留暂停目标，明确它暂停后续安排并终止当前run，不出现两个同义暂停按钮 |
| waiting_for_input | 补充输入 | 列出实际缺什么；禁止重新开始绕过门槛 |
| waiting_for_confirmation | 既有确认/拒绝门槛 | 不把普通“开始执行”放为更强动作 |
| interrupted且resumable | 继续执行 | 同task恢复；不生成新问答身份 |
| failed/degraded | 可用恢复动作或查看结果 | 失败原因、缺少的交付项；没有恢复能力时不造“重试”假按钮 |
| task终态且目标active | 查看/使用结果 | “确认目标完成”为次要显式动作，文案说明是用户确认完成条件；任务终态本身不代表学习目标完成 |
| Goal completed/cancelled | 阅读结果 | 不继续显示启用/开始的误导操作 |

列表保留目标状态，并在已有权威数据可得时突出“待你补充/确认”；不能为列表逐项新增高频runtime轮询。760用已有列表/详情切换，选择后标题与返回入口保留，返回恢复列表焦点。

定时说明精确写“仅在本地后端运行时执行”；实际是否补跑、如何错过处理必须根据后端核实后说明，不凭旧页面文案承诺。暂停、恢复、桌面退出fence属于行为验收，静图不能证明。

## C. 复习：每个推荐都接到一个可执行动作

当前结构基本可复用。去掉重复解释和缺乏行动的计数，将首页标题统一为“复习”。

- 顶部一块“今日复习”：到期错题数+推荐概念数，唯一“开始复习”；有未完成会话时合并为“继续复习 · 已完成x/y”，不要上下两个今日/继续卡片。移除“近期薄弱概念x个 · 近7天活跃x天”及按钮下重复“从…开始”，这些放入按需的活动区。
- 队列采用序号/主内容/动作三列；标题、原因、展开内容共用一条左轴，右端动作上对齐。删除每行重复“待复习”；只在实际记录中/失败/已记录时显示异常状态。760操作折到主内容下，不能挤压题干和公式。
- 到期错题保留“逾期x天/今日到期 · 章节”一行；“打开”改为“查看错题”避免误以为已开始重做。顶部开始复习进入现有持久化ReviewSession；若增加单题重做，必须复用该服务及恢复身份，不能仅改链接标题宣称已实现。
- 推荐概念收起时显示名称、一个具体推荐理由和“开始复习/展开”动作；累计接触、暂无复习记录、推荐权重归入详情。接触次数不是薄弱证据，不因重复问某概念就宣布薄弱。
- 概念展开后优先展示可读材料（已有教材片段和有效章节定位）、一条关联错题或近期卡点，接“去学习中继续理解”或“查看相关错题”。没有教材片段时只给可用入口，不并列三块“暂无…”空区。只有章节名没有有效定位时不能伪造可点击来源。
- “标记已复习”移到展开内容末端，写“记录本次复习”，用户自主确认才调用现有记录接口；点开、停留、阅读不能自动提交。当前质量值4不能表述为客观已掌握；保持现有调度映射，本轮不偷偷调整SM-2。若需困难/掌握程度自评，应单独对齐已有质量语义再做。
- 补充概念默认折叠；无时间戳不常驻“时间信息未提供”，在需判断日期的详情如实说明。队列返回数与真实到期总数不一致时仍显示“展示x/y”，不能用清理文案掩盖截断。
- 下部改为“学习记录”，默认折叠。高频概念只称“近期常见概念”，错题薄弱点须关联具体错题/错因；能点到证据和下一动作才有推荐价值，否则保持只读计数，不用AI式诊断结论。热力图是活动记录，不推断投入时长/掌握程度；无数据与零活动继续区分。
- “完善知识关联”不作复习主行动，留在记录详情或后续教材维护入口；其付费/数据出境确认语义保留。

空队列：一句“今天暂无到期内容”+继续学习；辅助统计/活动失败保留可用队列，按模块说明失败。不新增后台规划Agent或把所有重复记录改造成长期学习画像。

## D. 笔记：生成完成即读，用户保存才进入正式库

### D1. 复用已有能力，移除默认审核语气

`DraftEditor` 已通过 `draft.kind !== 'generation'` 决定初始编辑态，generation默认阅读。不能根据基线编辑图重复“修复”这个已存在的逻辑。须补验同一组件从生成中到editable的切换、导航返回、失败重试结果，确保kind与局部editing状态不会残留错误。

生成成功且完成回执/hash匹配 → **直接显示完整阅读文章**。页首为“笔记草稿”+轻量“草稿已保存”状态，右侧“编辑”和主动作“保存笔记”。无“审核/审阅完成/我已核对”步骤，无默认逐块来源或数学核验免责声明。可选人工编辑不作为保存前置条件。保存完成→正式笔记阅读页；默认阅读内容相同，只有状态和动作变化。

必须替换的文案：

| 现有 | 建议 |
|---|---|
| 正式笔记须审阅后保存 | 整理完成后可直接阅读，点击“保存笔记”加入笔记库 |
| 在会话三点菜单中选择“整理为笔记”，审阅后保存 | 从会话菜单选择“整理为笔记”，完成后可阅读、编辑和保存 |
| 逐块编辑 | 编辑 |
| 草稿列表：可编辑草稿 | 已整理，未保存为笔记（仅生成草稿）；其他kind保留准确标签 |

标题、正文、摘要沿阅读画布；摘要有内容才显示，不能与首段机械重复。编辑模式保留当前BlockEditor能力、可见字段标签、增删排序，但首屏不要重复文档标题+相同标题表单占两份大空间。现有顶部唯一正式保存入口保留；草稿自动保存状态是辅助反馈，不加第二个正式保存按钮。恢复/冲突条在正文之前，并保留VRB-02已验收的动作。

### D2. 状态与恢复

| 状态 | 展示/行为 |
|---|---|
| queued/running | 整理状态+可返回学习+取消；不先显示不完整候选为正式笔记 |
| completed且发布草稿成功 | 自动进入阅读，无额外审核门槛；未点保存仍在草稿 |
| failed/interrupted/cancelled | 来源保留，显式重试或手动整理；不自动付费重跑 |
| editable且用户编辑 | 草稿自动保存，读/编切换保留内容、焦点和滚动；离开保障沿既有editor |
| 草稿写入失败 | 保留文字，主“重试保存草稿”，可复制；正式发布不能绕过未成功flush |
| 草稿CAS冲突 | 保留当前内容，复制后重新载入服务器草稿；不静默覆盖 |
| 正式版本CAS冲突 | 复用复制修改并编辑最新版本；归档版本仅复制+阅读；不自动合并 |
| 正式保存成功 | 可继续阅读和再次编辑；修改通过新草稿+CAS发布新revision |

“直接阅读”与“明确保存”兼容：阅读是展示态，保存是正式资产提交；不能把生成成功自动写成正式note，也不能把用户点击保存当作数学验证通过。

### D3. 用户自主记录的实际边界

用户可主动整理、编辑、保存，以及在生成失败后手动整理，这些本轮必须通顺。**现有后端不支持无来源空白笔记，也不支持任意时刻调用manual创建**：manual要求已有snapshot，且该snapshot属于失败/中断/取消的生成请求；正式note的origins固定为session。不能只在NotesPage加“新建笔记”按钮然后传空snapshot，更不能先启动一次模型再取消来绕过约束。

若“自主记录”明确指完全独立空白笔记，需要另外实施 `user_added/manual` 来源合同、无source_snapshot时的校验/导出/编辑/历史兼容和迁移可行性评估；不得伪造Session。此项记为建议的功能增量，而非本轮视觉整理可以宣称完成。用户在生成后的文章中自由补充内容仍按现有user_added块语义处理。

## E. 练习与抽题：在现有模式中分工

现有practice/bank/import模式已有正确方向，不做全页重写。必须调整默认状态和解析区，把题库维护从作答主路径移开。

### E1. 练习首页与连续练习

- 保留“练习 / 题库 / 导入”切换；“手动录入”仅在题库/导入模式或空题库指引显示，练习进行中不常驻。若改为两层导航须另验返回状态，本轮无必要。
- 设置区名称“本次练习”，显示可理解的范围：教材/学科、实际生效筛选及已知可用题数。共用已有ScopeSelector提供修改入口，不能只写“当前题库”。题库搜索/状态若会影响抽题，必须在这里可见并可清除，不能隐形继承。
- 默认20题可以保留用户偏好，但提交前说明“本次最多n题，实际以可用题目为准”；已知确切只有2题时直接设为2。不能将本页最多100条加载结果当作整个题库准确总量；计数权威不足时注明“当前可用”。
- 顺序用有标签的“优先复习 / 随机”选择控件及选中状态，避免一个会改变名称的按钮使用户不知当前策略。开始为唯一主动作。
- 无题时提供导入/录入路径；有未完成会话时首屏优先“继续本次练习 · 已完成x/y”，不再用“设置本次练习”标题压住当前题目。
- 作答中布局为进度与暂停/结束 → 题干及来源 → 你的作答 → 参考答案与解析 → 自评与推进。主阅读宽度约740–800px；不在答案区强制lg两栏切碎长公式。题库总体统计留给bank，作答页只显示本轮进度。

### E2. 查看、反馈、记录的精确语义

现有“提交并查看解析”仅 `setPracticeSolutionOpen`，持久化由自评时 `submitPractice` 执行。最低风险且诚实的本轮方案：按钮改为“查看参考答案”；查看后显示“本题尚未记录，请核对后自评”，自评区域标题“记录本次作答”，按钮用“没掌握 / 基本理解 / 已掌握”，旁边明确“选择后记录并继续”。只有API成功后前进；失败保留本题、作答、自评与可重试操作。若用户要求真正先提交再反馈，应新增明确的领域状态支持，不能只保留旧文案。

打开参考答案后：答案以渲染后的LaTeX/Markdown只读呈现；解析单列接在后面，保留同题上下文。无标准答案时写“这道题尚无参考答案”，不显示一大片默认编辑器；可前往题库补充，不能把缺答案等价为自动判错。

不要给无判题服务的结果套“正确/错误”AI反馈。使用“你的自评”“参考答案”，学习记录来自真实作答与确认。错题转换继续走现有候选确认，不能因自评一次没掌握直接正式入错题本。

### E3. 答案维护与候选抽取

- `useExerciseAnswerJob` 保留持久化job、切题隔离和返回恢复能力。生成/编辑/保存标准答案移至题库详情的“维护参考答案”，练习阅读区至多一个次要入口。生成成功只产生答案草稿，需明确保存后更新题库；“引用x条”不能称准确性验证。
- job运行/完成/失败需要在对应题目下可发现；切题旧请求不得覆盖新题，后台完成不得覆盖用户正在手改的答案，保存失败不清空。已有hook能复用的行为先复用，缺失部分应补针对性测试。
- 抽题保持准备来源→校对候选→明确导入三个已有阶段。校对首屏优先题干/问题提示/编辑，原文可返回，已填字段仍有可见label；VRB-02布局不重新设计。
- 候选置信度降为辅助信息，错误/缺题干/答案边界问题优先；不新增“默认勾选即校对通过”的含义。选中、校对、入库是不同动作。
- 准备区的来源/章节/物理页标签填写后仍可见。把“低置信候选用文本LLM修复（默认DeepSeek，不做OCR）”改为用户任务语言“辅助修复文本候选”，说明只处理识别后的文字，并按真实角色配置描述服务；保留实际外部发送/费用确认，不写死供应商或把实现名当功能名。

## 3. 优先级与实施边界

| 优先级 | 本轮要求 |
|---|---|
| 必须 | Prompt按问题与理解程度解释；过程条轻量连续且保留诊断；Goal完成条件与当前任务层级、状态真实；复习减重复文字并接具体动作；生成笔记成功直接读、删除审核语气、保留明确保存与冲突恢复；练习范围清楚、作答/参考/自评/维护分离、按钮不虚称提交 |
| 建议 | 有稳定定位的概念材料直达；有真实证据的薄弱点到错题筛选；后台完成通知或导航轻提示的后续评估；独立空白笔记的来源合同设计 |
| 暂不 | 全局计时器/悬浮任务中心、重构Runtime、学习掌握推断、自动发布笔记、自动正式入错题、开放式Agent Loop、为本轮视觉工作新建数据库或第三套复习状态机 |

既有服务不具备的动作不得只靠改文案伪装完成。涉及来源合同、数据库/迁移或高风险架构调整时，按AGENTS先验证与用户授权；不以此阻断可独立完成的呈现、文案和已有状态修复。
