# Frontend route and feature inventory

Static source inventory, 2026-10-11. **NOT_TESTED** means the route/surface was not browser-driven in this audit. This file records mounted React routes and reachable UI actions from `Workspace.tsx`, `MainLayout.tsx`, page components and their feature hooks/API modules. No backend files were read and no product code was changed.

## Mounted routes and aliases

All pages below sit under `FirstRunGate` and `MainLayout`; each page is lazy loaded in a `PageSlot` with a per-path error boundary. The layout retains visited route outlets, so local component state, scroll, and active page streams can persist while another route is shown.

Route count: 18 rendered page patterns (with the two parameterized variants sharing component instances) plus `/settings` dialog redirect and two direct redirects (`/mistakes/review`, `/kg`). Query compatibility within `/mistakes` also replaces `?tab=review` to `/learning/review`, and `?tab=capture|entry` to `/mistakes/intake`. These legacy query triggers do not appear as visible tabs.

## Shared navigation, dialogs, drawers and hidden entry points

- **App rail:** `学习`, `目标与任务`, `复习`, `笔记`, `错题`, `练习`, `教材`, `设置`. `设置` opens a modal; rail collapse hides the learning-context sidebar. The route `/books` is reached through `教材`; “导入教材” from that screen routes to `/books/import`.
- **Learning context sidebar** (only relevant on `/`): `最近` / `归档` / `回收站`, new conversation, paginated session list, select session, per-session pin/unpin, organize as note, archive/restore, trash, undo; load more/reload and “查看未完成任务” appear after errors with blockers. Compact and overlay layouts start closed; scrim, close and “展开侧栏” control it.
- **Settings dialog:** tabs `偏好`, `模型连接`, `数据与教材`, `关于与更新`, `高级与诊断`. Preferences changes theme. Model tab manages reasoning/vision providers, split/native mode, profiles, custom endpoint/key, test, save/apply, revert; closing with unsaved model edits asks whether to discard. Data includes DataSafety create/list/restore backup, optional derived data, MinerU URL/CLI save. About shows version, desktop update check/download/restart-install and status; `MobileRemoteS0` shows actual backend port/Serve command and copy-token/refresh. Diagnostics can recheck system health, reload vector store, and opens NetworkDiagnostics. Errors are per tab with retry/status where available.
- **Context Inspector:** side panel supplied through InspectorContext; close button and feature-specific read-only context. It is not a route and closes on location/layout changes. Route-level inspector producers are in chat/learning components.
- **Note preflight dialog:** opened by chat/session “整理为笔记”; choose auto/concept/derivation/problem/comparison/review, completed-only, all vs selected turns, load older, resume existing draft/open existing note, generate draft, cancel/retry. Errors distinguish preflight and turn-list reads.
- **Highlights repository dialog:** launched from chat overflow and related feature action. Select book/chapter/section, open preview, generate/regenerate, cancel job, delete generated result; completion banner supports “稍后”/“点击跳转”. Loading/running gates action buttons; empty chapter/section lists depend on imported books. Direct `/highlights` remains the reader route.
- **Chat composer hidden/overflow actions:** stable input toolbar includes camera, image, textbook figure catalogue (disabled without book), historical mistakes; upload OCR correction; send/stop. Overflow menu adds set-as-goal (passes composer draft via router state), daily/weekly report, random exercise, view/generate highlights. The localStorage/event keys `texa:onboarding-first-question`, `texa:onboarding-awaiting-source`, `texa:onboarding-question-selected`, and `texa:onboarding-sourced-answer` still trigger first-question/source behavior without route navigation.
- **Other in-page overlays:** Exercise manual-entry dialog and textbook PDF page picker; Settings confirmation dialogs; browser `confirm` for goal completion, model-profile changes/deletion, and subject/book hide/delete. Mistake detail expands management/actions inline rather than opening a dialog. Dialog and overflow components supply their own close/dismiss behavior.
