# Texa 统一发展目标与实施 Handoff

日期：2026-10-06（Asia/Shanghai）。接手对象：Sol 及后续实施者。状态：**发展路线与分阶段交接；不是已完成实现或生产启用声明。**

本文件合并 Semantic Runtime / Evidence Gate / Context continuity 设计与宏观架构讨论，作为未来工作的统一排序入口。本轮只整理文档与 AGENTS 的未来目标，不改业务源码、依赖、模型配置、数据库或正式教材，不启动实施任务。

## 1. 方向与不可偏离的边界

Texa 是围绕教材、习题、错题、笔记与复习的本地智能学习工作区。长期积累依靠学习资产和真实记录，单次执行保持短、有界、可恢复。Agent 能力服务于学习流程，不将项目演变为通用 Agent 平台。

- 保持 FastAPI + React + Electron，桌面端优先；保留现有领域服务、Canonical IR、混合检索、模型角色工厂和 Runtime 安全边界。
- 主聊天继续是统一回答入口；页面明确操作直接调用领域服务，不必经过模型。直接操作、固定学习 workflow、有限组合任务共用身份/权限/验证/提交合同，但不强制走相同步骤。
- 一个活动 task 在任意时刻只有一个状态权威。Goal 是用户确认的目标，Task 是一次交付，Run 是一次执行尝试，Job 是异步承载，SSE 是传输；领域收据证明实际写入。
- 模型只能提出 candidate decision。scope、权限、确认、预算、fence、幂等、事务、合法状态转换、最终 verified 与不可逆执行由 deterministic Runtime 掌握。
- ContextPack 解释用户现在在说什么，EvidencePack 说明材料支持什么。历史 Assistant 内容不自动成为事实证据；完整会话不塞入 prompt。
- 不扩大开放 Agent loop；动态补偿保持既有受限数学 verification_request 的至多一轮边界。学习 Goal 可以长期存在，但每次运行是有限任务，不依靠模型持续运行维护进度。
- 工具围绕完整学习动作组织，复用领域服务；不让模型拼接大量底层 CRUD/检索步骤，也不在粗粒度工具内隐藏写操作。
- 学习资产保存、写入和目标启动遵守既有用户确认边界；不把自动生成回答直接变成正式笔记、错题或掌握度。
- 借鉴成熟通用 Agent 的工具合同、任务分流、恢复与结果验收；产品上借鉴任务可见、结果可检查、可中断与可编辑，不照搬 Coding Agent 的长上下文、多 Agent 和开放自主规划。

## 3. 优先级与远近排序

P1 表示核心正确性/资产安全/学习闭环，P2 表示效率与能力增强，P3/P4 表示后续产品扩展，P5 表示条件性研究。**近期/中期/远期是依赖顺序，不是日历或工期承诺。**已证实的数据破坏、越权或不可恢复事故随时提升为 P0 中断其他工作，不以本路线排期掩盖事故。

| 工作包 | 优先级 | 时段 | 交付目标 | 依赖 |
|---|---|---|---|---|
| H0 基线与剩余差距 | P1 | 立即 | 区分已修复、目标差距、待验收和未知，固定接手版本 | 无 |
| H1 答案与证据真实性 | P1 | 近期第一批 | 最终可见证据、逐项交付、验证与发布身份贯通；取消语义启发式的最终拒答权 | H0 |
| H2 执行权威与恢复收口 | P1 | 近期第一批 | 一 task 一权威；直达/workflow/有限组合共用状态合同，停止恢复不串线 | H0；与 H1 按接口协调 |
| H3 真实教材与学习闭环验收 | P1 | 近期持续 | 真书/图片题/习题/错题/复习/Notes 和 Electron 的可追溯闭环 | H0 可准备；发布依赖相关 H1/H2 |
| H4 ContextPack 局部连续性 | P1 | 近期第二批 | 1–5 轮理解投影、最多2轮生成原文；纠正、歧义、证据重用不串事实 | H1/H2 合同稳定 |
| H5 学习资产关联与进展证据 | P2 | 中期第一批 | 稳定来源关联、独立资产检索，答案质量与学习进展分开 | H2/H3 |
| H6 学习动作工具与 Goal/提醒 | P2 | 中期第一批 | 少量完整领域能力；长期目标通过短任务和本地调度推进 | H2；H5 提供进展来源 |
| H7 PolicyLM 渐进接入 | P2 | 中期第二批 | 独立共享角色，off→shadow→分 task assist，有限日志与审阅数据集 | H1/H2/H4 + 基线审阅 |
| H8 桌面性能与发布工程 | P2 | 近期起持续 | 按需加载、首屏/延迟优化、离线能力、包身份、备份与回滚 | 分阶段跟随 H1–H7 |
| H9 章节学习与移动验证 | P4 / P3 | 远期 | 章节例题主线与阶段总结；在桌面稳定后验证移动/PWA | H3/H5/H6/H8 |
| H10 开放自主能力评估 | P5 | 条件性研究 | 只有明确业务收益与安全证据才评估，不默认建设 | 核心闭环成熟后另行决策 |

H8 中影响安全的备份恢复、包版本身份和升级可靠性是相关版本的发布门槛，不能因“性能包 P2”而后移。H3 包含持续教材质量规模化，不因第一本书通过而结束。

## 4. 近期实施交接

### H0：先确认当前差距

- 阅读当前 git diff、修复记录及其 manifest；记录关键文件摘要、实际运行端、模型角色/提示词/索引版本，避免用 HEAD 代替工作树。
- 对 A01–A11 逐项标记 `implemented_pending_validation / partial / not_started / unknown`，只保留本轮相关差距，不泛化重做全链路审计。
- 重点确认：最终正文是否仍被二次裁剪、旧 focus 是否仍有清空候选权、scope 是否自动切通用、所有入口是否消费同一映射、Job success 是否被误读为 verified。
- 产物：版本基线与剩余问题表。可复用修复测试，不因为旧文档要求再次实现已有功能。

### H1：先保真实性，再取消错误阻断

复用现有 `graph/evidence_pack.py`、generator/chapter 共享准备入口、answer_verification 与 exercise_answers 服务。详细合同参见语义设计第5–7节。

1. 冻结 generator 实际可见的正文、E-id、scope/版本、outputs 合同；任何再裁剪/重编号都使 coverage 失效。
2. 简单问题保持轻量 output；复杂多问才展开依赖。区分理解完整性、证据覆盖、答案正确性，不能由一个 supported 代表三者。
3. coverage 为 supported/partial/missing/ambiguous；结构 passed 不代表数学 verified。逐项消费本题公式、单位、数值和工具收据；无法核验保留未知。
4. 新 gate 与验证发布边界准备好后，原子撤销语义/词法拒答与自动扩大范围的权力。原问句保留，同范围检索默认继续；纯无对象指代允许局部澄清，不能说教材不支持。
5. QA、teach/summarize、图片题、习题、Runtime/Goal 接入同一发布合同，保留各领域流程；不重建第二条回答链。

完成标准：裁剪不可见事实不能 supported，缺 E-id 正文不能通过，复杂多问不能遗漏却完整成功，错误公式不能借符号相似通过；问法变化仍有检索机会；不扩大用户范围。支持部分可交付，内部验收信息按需展示，不恢复 Notes 已废弃的逐块警告或额外勾选。

### H2：收口任务所有权，不做全库迁移

- 梳理 LearningTask、SQL Runtime、Job、Goal、执行事件的 owner/状态/恢复接口；明确一个 task 的唯一权威，不允许故障后改投另一个任务存储继续写入。
- 统一“读取快照、等待输入、确认、停止、恢复、提交 outcome”的应用合同；旧/新存储可由适配器并存，SSE 和前端只投影事实。
- Job 完成只说明该异步计算结束；Goal 是否完成依据用户确认及其契约；领域写入成功依据收据，未知写入不得自动重试。
- 普通手工 CRUD 不经过模型；直接回答、固定 workflow、有限组合任务允许不同执行长度，共用必要检查。

完成标准：重复提交、断流、重启、旧 run 迟到、scope/revision 变化均不重复写入、不串 task、不伪造 completed；习题同次生成恢复的未验收项独立报告。没有必要性和独立授权不迁移数据库。

### H3：真实学习闭环和资产质量

- 沿已有矩阵验证：教材→问答→追问/纠正→主动保存笔记→候选习题人工校对→作答→错因归档→到期复习→重启后定位。
- 图片题覆盖缺页、附表、用户校正、公式/数值；教材覆盖定义、列举、比较、原理、推导、应用、跨章及多书来源。
- 真实教材人工黄金集与 OCR/公式/表格审阅持续扩展；staged candidate 通过生产混合检索与 FinalPack 门槛后才考虑正式激活。
- 原审计 A09/A10、F01/C04 未知根因和 Electron 未验收项保持独立状态；不借架构更新宣称它们已解决。

完成标准：按事实覆盖、数学检查、来源、持久一致性分别验收；不能以测试总数替代。真实模型调用须预先明确发送范围/调用上限/预算并授权；正式资产切换、安装包与桌面验收另有版本证据。

### H4：局部语义连续性

- 在 session_context/session_ledger/conversation_context 上演进，不建第二套记忆服务；解析前 CP 与解析后生成投影分开。
- 最近1轮优先原文摘录和完整必要条件，稍远最多4轮结构化，更远摘要带来源；生成器最多2轮相关原文，不默认装满窗口。
- 独立新问题不继承旧约束；用户纠正优先；多个指代候选允许 ambiguous。检索某对象材料更多不能证明用户指的就是它。
- evidence reuse 只复用经过版本校验的来源候选，每轮重新构建可见 Pack 与 coverage；旧 supported 不继承。

完成标准：1–5轮局部场景及20/40/80轮分层评测均覆盖 correction/artifact/clarification/continuity/standalone；成本不随完整历史线性增长，Assistant 错误不进入事实证据。

## 5. 中期实施交接

### H5：资产关联与真实学习状态

保留教材、SessionNote、Exercise、Mistake、学习事件等独立权威，逐步补稳定引用：讲解→笔记来源、习题→作答、作答→错因、错题→概念/教材位置。缺少历史身份保留 unknown，不从当前索引静默补绑。优先改公开服务接口与查询投影，不建立万能资产大表。

答案质量记录理解/证据/公式/完整性；学习进展记录实际作答/复习/用户确认。接触、理解自评与独立作答表现分别表示，模型印象不自动提升掌握度。资产浏览、编辑和复习记录在模型离线时仍可用。

验收：从错题回到原作答和教材位置，从概念找到相关学习资产；删除/归档会话不级联删除独立资产；幂等与来源版本一致。无来源或无作答证据时不伪造精确掌握概率。

### H6：工具、Goal 与提醒

优先封装“完整例题/定义与条件/关联错题/到期候选/练习集合提案”等领域能力，内部复用检索、IR 和服务。保留 schema、provenance、权限、输入完整性与预算，不无限扩工具目录。

Goal 仍由用户确认，长期存在但以有限 task 推进；本地 Scheduler 只触发已授权短任务，不让模型持续维护长计划。先利用现有 SM-2/错题/ConceptMemory 做提醒和简化进度，避免增加一套 AI 调度器。未知写操作、关键输入、审批不被定时触发绕过。

验收：提醒有学习记录依据，关闭桌面不宣称云端继续执行，重启不自动付费重跑；proposal→确认→领域收据可追溯。复习会话等缺失领域能力单独补齐，不由模型自由调用 CRUD 拼状态机。

### H7：共享 PolicyLM，但分任务接管

统一形式仍为 `RuntimeObservation/ContextPack + PolicyTask + AllowedCandidates → candidate PolicyDecision`。同一模型角色可共享，调用按需；不把各任务串成每轮必跑的模型链。

接管顺序：reference/intent/required outputs → context relevance → evidence coverage → 再评估 action ranking/Goal state。先 off/shadow，再按 task 校准 assist；0/1动作候选保留无模型路径。现有理解/语义适配器收为兼容入口，避免重复调用。无0.8B时完整保留 H1–H6 的运行能力。

强模型 fallback 只用于已定义复杂 case，受角色配置、数据授权、次数与预算约束；未配置不自动借用回答模型。invalid/unknown/timeout 不扩大范围，不授予 verified。

RuntimeEvent 只保存有限元数据和引用；完整 Policy Dataset 通过授权来源重建、脱敏、人工审阅、冻结版本形成。shadow 分歧、task completed、用户无反馈都不是正确性标签。旧 Policy V0 冻结基线保留，新合同差异单独审阅。

验收：off 无额外模型 IO，shadow 无业务副作用，stale 决策不可执行；分 task/长度/负例报告 precision、歧义保留、证据召回、错误阻断和假成功，样本不足不接管。0.8B 参数规模不作为能力证明。

### H8：性能、离线和发布贯穿各阶段

先测 p50/p95、首个有效内容时间、模型调用数、内存与失败恢复，再优化。优先按需加载 KaTeX/Markdown、资源和模型角色，非必要 IO 惰性解析；避免同请求重复规划/检索/理解。教材导入、后台任务与交互问答采用有界并发和取消边界，不抢占到使前台不可用。

模型/网络不可用时，教材阅读、笔记编辑、已存答案、练习记录与复习队列继续可用；依赖缺失对相关能力局部降级。性能优化不能裁掉证据条件或绕过 gate。

每次发布绑定代码、前端产物、打包后端、模型配置版本与索引身份；验证隔离副本的备份/恢复/升级回滚。macOS 原生、Windows 原生和安装包分别报告，未测为 not_run。

## 6. 远期与暂缓

- H9：章节学习仍以已有教材例题、练习和阶段成果为主线，不靠模型现场造题。移动/PWA 在桌面核心稳定后验证布局、离线和提醒可行性，不预设手机承载整个桌面后端。
- H10：多 Agent、开放自主 loop、通用插件平台、长上下文管理、复杂 AI 学习规划均不进入默认实施范围。只有现有路径无法完成的明确场景、可衡量收益和独立安全/成本评测才启动新设计。
- 端侧权重选择、下载、训练和模型部署不是 H7 接口预留的隐含授权；数据库迁移、供应商切换、正式索引激活也不是本 handoff 的隐含步骤。

## 7. 统一完成标准、回滚与交接格式

所有阶段同时观察两类错误：**本可回答却被阻断**与**依据不足却宣布成功**。另看用户是否完成了学习任务及记录是否准确保存。不能只优化工具成功率、回答长度或总体平均分。

最低发布证据分四层：合同/故障注入 → 真实索引与人工事实覆盖 → 获授权的真实模型 → 原生 Electron/相关安装包。按阶段运行适用层，未运行不记通过；继承既有测试，不机械增加测试数量。

每个实施包交付：

1. 起始源码/数据合同版本、前置条件与明确范围。
2. 已复用实现、实际改动及公开接口变化；不得根据旧行号盲目重建模块。
3. case级验收、命令/环境、失败与未测项；日志无密钥和正文。
4. 开关/版本兼容/旧 checkpoint 行为、回滚操作与不会自动重放的事项。
5. 下一包依赖与剩余风险；普通修复写 patch_notes，长期约束实施后再更新 AGENTS 当前架构部分。

回滚优先关闭新模型 task、退 shadow、恢复上一安全适配器；不恢复已知“缺正文也 passed”的宽松门槛。gate/generator/verifier 同版本切换，不能出现撤旧 gate 后新 gate 未生效的窗口。无法安全重建的旧 checkpoint 明确 stale，不用新索引冒充；历史权威消息与领域收据不因回滚改写。

## 8. 与旧 M0–M6 的对照及第一步

| 语义设计阶段 | 统一工作包 |
|---|---|

| M1 身份 / M2 输出验证 / M3 gate 切换 | H1，并由 H2/H3 验证恢复与业务接线 |
| M4 continuity | H4 |
| M5 shadow / M6 分 task assist | H7 |
| 原设计未展开的宏观能力 | H2、H5、H6、H8、H9；均复用已有领域边界 |

**下一实施任务从 H0 开始，随后完成 H1 的剩余差距与 H2 的接口收口；H3 的数据准备和 H8 的发布身份检查可同步推进。不要先装小模型，不要先全量迁库，也不要先重构整个 Runtime。**本轮把这些内容确立为未来发展目标，具体实现应在接手任务中按工作包执行。
