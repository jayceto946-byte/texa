# Reference harnesses

Use mature productivity products as abstract evidence, not as a parts catalog.

## Codex reference principles

OpenAI describes the Codex app as a focused space where work is separated into threads organized by project, users can switch tasks without losing context, inspect results within the thread, and reuse existing session history. Extract these principles:

- persistent organizational context reduces re-selection
- a dominant thread workspace makes the current task unambiguous
- history is dense because rows use hierarchy, not cards
- status remains near the work it describes
- review detail appears on demand instead of occupying the primary surface
- secondary actions stay in toolbars, menus, and inspectors

Few cards are needed because the shell, selection state, spacing, and dividers already express hierarchy. Density stays calm through a restrained type scale, consistent row height, muted metadata, alignment, and one accent.

Do not copy OpenAI identity, logo, colors, exact spacing, exact dimensions, iconography, composer shape, or page composition.

## Other references

- Linear: compact selection, command clarity, predictable list-detail transitions.
- VS Code and mature IDEs: persistent project context, explicit panels, keyboard accessibility, stable tool locations.
- Raycast: concise functional copy, strong keyboard flow, low ornamentation.
- Arc-style productivity UI: contextual controls and disclosure without ornamental chrome.
- Claude desktop productivity surfaces: readable conversations and restrained secondary controls.

## Texa synthesis

Build a single Texa grammar rather than assembling recognizable parts from other products. Texa identity comes from textbook scope, learning sessions, evidence language, concept inspection, mistake review, and actionable progress.
