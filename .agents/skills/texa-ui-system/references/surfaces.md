# Surfaces

## Hierarchy

Use only application background, primary workspace surface, subtle secondary surface, selected state, and true floating elevation.

If spacing can express separation, do not add a card. If a divider can express separation, do not add a shadow.

## Radius

- Small: 4px for compact rows and small controls.
- Medium: 8px for buttons, inputs, popovers, and grouped containers.
- Large: 12px for modal or dialog shells only.

Use pills only for true tags, filters, or compact status with pill semantics. Do not make ordinary buttons, tabs, scope selectors, answers, or navigation pills.

## Borders and shadow

Use 1px neutral hairlines. Avoid a border around every child. In lists, prefer one group boundary plus row dividers. Use dashed borders only for drop targets or unpopulated upload areas.

Default shadow to none. Use one restrained shadow token only for menus, popovers, modals, and floating inspectors.

## Conversation

- User question: compact differentiated block, not a giant bubble.
- Answer: open document flow on the workspace surface.
- Evidence: compact source row plus inspector.
- Concept: inline link or compact metadata row when inspectable.

## Library and settings

Use split views and list rows. Do not wrap a split view in a card and then wrap every row in another card.
