# Interaction

## General

Make controls contextual, keyboard-first, and low in visual weight. Keep common actions visible and move low-frequency actions into a More menu, attachment menu, or inspector.

## Composer

- Keep input focus visually clear and use a stable bottom location.
- Keep send as the single dominant action.
- Keep attachment and math input available without a floating pill or icon crowd.
- Reserve an extension point for image input without pretending unavailable features exist.
- Preserve the established submit shortcut and multiline behavior.

## Progressive disclosure

Use disclosure for source detail, concept detail, metadata, advanced settings, archived items, and long technical logs. Do not hide current scope, active repair, or the primary action.

## Keyboard and focus

- Preserve visible focus for every interactive element.
- Support Escape to close menus, dialogs, drawers, and inspector.
- Keep tab order consistent with visual order.
- Never rely on hover alone.
- Use semantic button, link, input, and heading elements.

## Buttons

Use only primary, secondary, ghost, danger, and icon variants. Each page should normally have one dominant primary action. Disable only when the user can understand why.

## Motion

Use short transitions for panel, menu, collapse, focus, and small state change. Use 90 to 180ms, respect reduced motion, and animate transform or opacity only when useful. Do not use page entrances, flying cards, gradient animation, bounce, decorative shimmer, or perpetual motion.

## Copy

Use short, specific, functional Chinese. Avoid `AI-powered`, 智能赋能, 探索, 开启旅程, 魔法, 全新体验, and repeated reminders that the system uses AI.
