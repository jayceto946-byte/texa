# Design principles

## Product definition

Texa is a learning harness, not a SaaS dashboard.

Texa is a desktop learning workspace organized around textbooks, learning context, sessions, retrieval, questions, answers, sources, concepts, mistakes, exercises, and long-term review. It is not an AI landing page, chatbot wrapper, analytics dashboard, Notion clone, ChatGPT clone, or Codex clone.

## Personality

Make Texa quiet, precise, academic, modern, focused, trustworthy, tool-like, and stable. Combine learning-tool semantics, developer-grade harness clarity, and consumer desktop usability.

Avoid playful SaaS, futuristic AI, cyberpunk, glass UI, luxury dashboard, cute education app, and corporate analytics styling.

## Decision order

1. Information architecture
2. User flow
3. Layout
4. Component system
5. Typography
6. Visual polish
7. Motion

Do not use polish to conceal unresolved structure.

## Core rules

- Optimize for several hours of daily study, not a five-minute demo.
- Let learning objects and evidence carry identity. Do not make the model the product hero.
- Prefer persistent context to repeated selectors and confirmation dialogs.
- Prefer predictable paths to artificially low click counts.
- Use progressive disclosure for secondary evidence, metadata, and system detail.
- Preserve useful Texa identity: the name, book semantics, blue accent, math-rich typography, and local-first status language.
- Evolve with structural correction. Do not wipe working business flows.

## Review questions

- Is the primary learning task obvious within one glance?
- Is the current textbook or scope visible?
- Can the user resume a session without reconstructing context?
- Does each surface have one dominant job?
- Is information removed only when it is genuinely secondary?
- Would the interface still feel like a learning tool if the logo disappeared?
